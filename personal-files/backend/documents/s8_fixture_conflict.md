# S8.json 금지 구문 내부 충돌 분석

작성일: 2026-05-02  
대상 파일: `docs/spec/specs/S8.json`

---

## 충돌 위치

S8.json 안에서 AI summary 금지 구문을 두 군데서 정의하고 있습니다.

### 위치 A — line 1782 `ai_summary_quality.disallowedPhrases`

```json
"disallowedPhrases": [
  "다음 구역 추천",
  "누락 확정",
  "위험도 높음",
  "자동 판단"
]
```

### 위치 B — line 2123 `harness_constraints.forbidden` (배열 내 텍스트 한 줄)

```
"AI summary에 추천, 누락 확정, 위험도 판단, 다음 구역 지시 포함 금지"
```

---

## 두 정의를 나란히 비교

| 순서 | A (1782 disallowedPhrases) | B (2123 forbidden 텍스트) | 상태 |
|------|---------------------------|--------------------------|------|
| 1 | `다음 구역 추천` | `추천` | 범위 다름 |
| 2 | `누락 확정` | `누락 확정` | 일치 |
| 3 | `위험도 높음` | `위험도 판단` | 문구 다름 |
| 4 | `자동 판단` | `다음 구역 지시` | 완전히 다른 구문 |

일치하는 건 `누락 확정` 하나뿐입니다.

## 구문별 분석

### 1. `다음 구역 추천` (A) vs `추천` (B) — **A가 너무 좁음**

A는 `다음 구역 추천`이라는 구체적 표현만 막습니다. 그러나 AI summary의 역할은 경로·마커·구역 상태·메모를 **사실 그대로 나열**하는 것입니다 (S8.json:1781 `sourceSnapshotPolicy`). 어떤 형태든 AI가 견해나 권고를 표현하는 것 자체가 역할 위반입니다.

```
// A(1782) 기준: 통과 ← 이게 문제
"이번 수색에서 체력 소모가 많은 팀에게는 단거리 경로를 추천합니다."

// B(2123) 기준: 차단
"이번 수색에서 체력 소모가 많은 팀에게는 단거리 경로를 추천합니다."
```

`다음 구역 추천`만 막으면 AI가 다른 형태의 추천 문장을 자유롭게 생성할 수 있습니다.  
→ **이 구문은 B의 넓은 `추천`이 도메인 의도에 더 가깝습니다.**

---

### 2. `위험도 높음` (A) vs `위험도 판단` (B) — **둘 다 불완전**

A는 `위험도 높음`이라는 특정 레벨 표현 하나만 막습니다. 그러나 `위험도 낮음`, `위험도 중간`, `위험도 매우 높음` 등은 모두 통과합니다. AI가 위험도를 어떤 레벨로 단정하든 동일한 위반입니다.

```
// A(1782) 기준: 차단
"북쪽 구역의 위험도 높음으로 판단됩니다."

// A(1782) 기준: 통과 ← 이게 문제
"북쪽 구역의 위험도 낮음으로 판단됩니다."
"현재 상황의 위험도 중간 수준입니다."
```

B의 `위험도 판단`은 의미가 다릅니다. "위험도 판단을 내려야 합니다"처럼 **사람이 판단해야 한다는 문장**도 잘못 차단합니다.

```
// B(2123) 기준: 차단 ← 이건 막으면 안 됨
"현장 지휘관이 위험도 판단을 내려야 합니다."
```

→ **A는 레벨 하나만 막아서 좁고, B는 엉뚱한 문장을 막아서 방향이 틀렸습니다.**

#### 추가 복잡성: 마커 인용 vs AI 직접 판단

사람이 직접 "위험도 높음" 마커를 생성했다면 AI가 그것을 인용하는 건 사실 보고입니다.

```
// AI가 스스로 판단 → 위반
"이 구역은 위험도 높음입니다."

// 사람이 만든 마커를 보고 → 정상 요약
"3구역에 '위험도 높음' 마커가 1건 태깅되어 있습니다."
```

단순 문자열 매칭으로는 이 둘을 구분하기 어렵습니다. `위험도` 전체를 막으면 정상 요약도 차단됩니다.

---

### 3. `자동 판단` (A에만 있음) vs `다음 구역 지시` (B에만 있음) — **A가 옳음**

```
// A(1782) 기준: 차단
"시스템 자동 판단 결과, 3구역이 미수색입니다."

// B(2123) 기준: 통과 ← 이게 문제
"시스템 자동 판단 결과, 3구역이 미수색입니다."
```

`자동 판단`은 ADR-0027 자동 판단 금지 원칙과 직결됩니다. B에서 이 구문이 빠진 것은 도메인 원칙을 탐지하지 못하는 가장 심각한 누락입니다.

B의 `다음 구역 지시`는 `추천`으로 이미 커버되는 범위와 겹쳐 불필요합니다.

---

## A와 B 중 어느 쪽도 온전하지 않다

| 구문 | A (1782) | B (2123) | 판정 |
|------|----------|----------|------|
| 추천 관련 | `다음 구역 추천` — 너무 좁음 | `추천` — 범위가 맞음 | **B 방향이 옳음** |
| 누락 확정 | `누락 확정` | `누락 확정` | 일치, 유지 |
| 위험도 | `위험도 높음` — 레벨 하나만 | `위험도 판단` — 방향 틀림 | **둘 다 불완전, 별도 결정 필요** |
| 자동 판단 | `자동 판단` — 핵심 원칙 | `다음 구역 지시` — 중복·불필요 | **A가 옳음** |

현재 fixture(`S8HandoverAiFixtures.java`)는 A 기준으로 수정되어 있지만, 위 분석에 따르면 A도 완전하지 않습니다.

---

## 이전 fixture가 B를 따른 이유

`S8HandoverAiFixtures.java`의 기존 주석이 `S8.json line 2123`을 참조하고 있었습니다.  
2123은 사람이 읽는 설명 텍스트 형식이어서 구현자가 자연스럽게 그 문장에서 구문을 추출했습니다.  
1782의 `disallowedPhrases` 배열은 별도 섹션에 있어서 참조가 누락되었습니다.

---

## 현재 상태

`S8HandoverAiFixtures.java`의 `FORBIDDEN_AI_SUMMARY_PHRASES`는 A(1782) 기준으로 수정된 상태입니다.

```java
public static final List<String> FORBIDDEN_AI_SUMMARY_PHRASES = List.of(
        "다음 구역 추천",
        "누락 확정",
        "위험도 높음",
        "자동 판단"
);
```

그러나 위 분석에 따르면 이 목록도 재검토가 필요합니다.

## 미결 결정 사항

spec을 수정하기 전에 아래 두 가지를 결정해야 합니다.

### 결정 1: `추천` 범위

| 선택지 | 내용 | 결과 |
|--------|------|------|
| `다음 구역 추천` (현재 A) | 다음 구역 지시만 차단 | AI가 다른 형태의 추천 문장 생성 가능 |
| `추천` | 모든 추천 표현 차단 | AI summary에 견해·권고 표현 전면 금지 |

AI summary가 순수 사실 요약이라면 `추천` (넓은 범위)이 원칙에 맞습니다.

### 결정 2: `위험도` 처리

| 선택지 | 내용 | 결과 |
|--------|------|------|
| `위험도 높음` (현재 A) | 레벨 하나만 차단 | 다른 레벨 표현 통과 |
| `위험도` 전체 | 모든 위험도 언급 차단 | 마커 인용 같은 정상 요약도 차단될 수 있음 |
| 레벨 열거 | `위험도 높음`, `위험도 낮음`, `위험도 중간` ... | 관리 부담, 새 표현 누락 가능 |

마커 인용 허용 여부 (따옴표 처리 등)와 함께 결정해야 합니다.
