v1.3 검토 필요 / 미정

  • 마커 SVG 디테일: 현재 inline path는 시안. high-fi에서 Lucide·Tabler·Material Symbols 중 라이브러리 결정 + 디테일 정교화 필요
  • 경찰견 아이콘: 시안 path가 다소 거침. high-fi에서 다듬기
  • 마커 라벨 토글 UX: default ON이라 좌측 패널에 새 항목 추가됨. 사용 빈도 검증 후 default OFF/ON 결정
  • 운영 메모 라벨: 사용자 화면은 "운영 메모"/"메모"로 통일. 영어 enum "NOTE"는 API/debug 맥락 전용.
  • cluster 안의 마커: cluster 클릭 시 sub-type별 그룹 표시? 아니면 zoom-in?
  • 마커 라벨 collision: 같은 좌표 근처에 마커 여러 개 + 라벨 모두 ON이면 라벨 겹침. cluster 임계 + 라벨 stack 정책 high-fi 단계
  • 지도 범례 길이: 마커 7종 추가로 범례가 길어짐. 좌측 하단 max-width 320px에서 줄바꿈 발생. 범례 grid 정리 필요
  • 실종팀 영역 표시: 이전 시도부터 미정 — UNIT 외부 실종팀 free roam. 현재 v1.3에서도 미반영

Codex 재검수 (PRD/spec 대조 · 2026-05-05)

검수 기준: `docs/prd.md`, `docs/spec/harness-scenarios.md`, `docs/spec/boundaries.md`를 기준으로 v1.3 main canvas와 review variant를 대조했다. 브라우저 검증은 1920×1080 Playwright viewport에서 수행했고, favicon 404 외 콘솔 오류는 없었다.

반영 확인

  • PASS PRD의 SearchArea 3계층(`OVERALL | UNIT | TEAM`)과 README의 OVERALL → UNIT → TEAM 흐름이 main canvas와 우측 트리에 반영됐다.
  • PASS OP current와 selected overlay가 분리되어, PRD FR-11/FR-32의 OP 비교 요구와 anti-pattern의 "동시 active OP" 금지에 맞는다.
  • PASS 현장 마커 기본 타입 5종(`CLUE`, `PERSON_FOUND`, `FIELD_CONDITION`, `SUPPORT_REQUEST`, `NOTE`)과 지원 요청 subtype 3종(`DRONE`, `POLICE_DOG`, `OTHER`)이 UI에서 식별된다.
  • PASS 폴리폰 최신성은 `60초 이내 / 1분 이상 / 5분 이상` 기준으로 spec의 stale/lost 기준과 맞는다.
  • PASS `incident_closed` variant가 실종자 정보와 실시간 위치를 제거한 tombstone 방향으로 바뀌었다.

수정 필요

  • FIX 지원 요청 마커의 지도 chip이 `드론`, `경찰견`만 표시된다. PRD는 외부 수색 자산의 실제 투입·승인·경로 표시를 범위 밖으로 두고, 무전/공식 채널로 전달한 지원 요청 위치 기록만 다룬다. `드론` 단독 라벨은 실제 드론이 배치된 것처럼 보일 수 있으므로 `지원: 드론`, `지원: 경찰견`, `지원 요청`처럼 요청 상태가 드러나야 한다.
  • FIX `toast` slot 검증이 빠져 있다. boundaries의 board slot에는 `toast`가 `SUPPORT_REQUEST_CREATED`, `PERSON_FOUND` 알림을 담당하고, PRD/SC-08은 지원 요청·실종자 발견 알림 도달을 검증한다. main canvas 또는 state variant에 `지원 요청 toast`, `실종자 발견 강조 알림`, dismiss/stack 정책을 다시 넣어야 한다.
  • FIX 헤더의 `수색 이력 요약` 버튼은 생성 CTA인지 조회 CTA인지 불명확하다. SC-11은 OP1 구역 완료, OP2 전환, 인수인계 메모 저장 전에는 생성 CTA/API가 열리지 않아야 하고, 비지휘 계정은 생성 CTA가 노출되지 않아야 한다. `요약 보기`와 `요약 생성/다시 시도`를 분리하고, eligibility/FAILED/loading variant를 명시해야 한다.
  • FIX member role variant에서 `수색 이력 요약`이 활성 버튼처럼 남아 있다. 사건 배정 대원은 기존 요약 조회는 가능할 수 있지만, 생성/재시도는 `현장 지휘관` 권한이다. member variant는 `요약 보기`만 허용하거나 `요약 생성`을 숨김/비활성으로 표시해야 한다.
  • FIX `incident_closed` variant의 `파기 진행: 실종자 정보 ✓ · 위치 좌표 ✓ · 단말 로컬 ✓`는 tombstone 허용 필드와 표현을 더 좁혀야 한다. boundaries는 public tombstone을 `incidentId`, 종료 상태/시각, 쓰기 불가 사유, 사용자 노출 가능한 `localPurgeState` 수준으로 제한한다. 세부 내부 파기 항목처럼 보이지 않게 `로컬 정리 상태: 완료/대기` 정도로 축약한다.
  • FIX SC-12는 사건 종료 확인 다이얼로그가 삭제 대상과 재오픈 불가를 승인 전에 표시해야 한다. 현재 review에는 종료 후 tombstone만 있고, 종료 승인 전 confirm variant가 없다. `사건 종료` 화면/다이얼로그 산출물에서 반드시 보완해야 한다.

검토 메모

  • 메모 지도 라벨과 SVG 마커가 많이 좋아졌지만, 실제 Playwright/Linux 검수 환경에서는 한글 glyph가 여전히 네모로 보인다. 폰트 설치 전제를 문서화한 것은 맞지만, 산출물 공유/CI 검수까지 고려하면 로컬 폰트 번들 또는 screenshot 검수 환경 고정이 필요하다.
  • 메모 main canvas 우측 패널은 내부 스크롤이 생긴다. UNIT 접기/펼치기가 들어와 사용성은 개선됐지만, high-fi에서는 접힘 상태의 기본값과 "stale/lost 폴리폰이 있는 UNIT은 자동 펼침" 같은 정책을 검토할 만하다.
  • 메모 FR-13은 구역 클릭 시 `완료 이력: N회`처럼 `search_area_history` 기반 이력을 표시해야 한다. main board에서 모두 보여줄 필요는 없지만, 구역 상세/hover/우측 detail variant에서는 완료 이력 표현을 추가해야 한다.

판정: v1.3 main canvas는 웹 상황판 기본 구조와 마커 시각 체계 검증용 low-fi로는 통과 가능하다. 다만 PRD/spec 기준 완성도를 보려면 다음 화면으로 넘어가기 전에 위 FIX 중 `지원 요청 라벨`, `toast slot`, `수색 이력 요약 CTA 상태`, `incident_closed/close confirm`은 v1.4 또는 별도 state artifact로 정리하는 편이 안전하다.
