## 실제 상황판에서 무엇이 막혔는가

00:58:06.815 KST에 같은 사건·수색 차수를 열고 제품 계측을 켰다. 새 GPS·마커는 보내지 않았으며 페이지 한도도 변경하지 않았다. 화면은 1440×900, DPR 1이었다. 이전 완료 캡처는 1260×990이고 지도 중심·확대 수준도 정확히 복원하지 못했으므로 완전히 동일한 화면 조건은 아니다. Aside의 `setViewportSize` 호출은 지원되지 않아 측정 시작 전에 실패했다.

**진단 개입 전 188.324초 관측:**

- 경로 조회 146건 완료, 구간 11,120개 수신·캐시 반영. 경로 조회 실패·수집된 브라우저 오류 0건, 최대 동시 요청 1건이었다.
- 지도에 경로를 전달한 계측과 첫 경로 렌더링 계측이 없었다. 실제 지도에도 `operational-movement-path` source가 없었다.
- 배경·건물·마커 source는 존재했다. 관찰 시점에 따라 마커 source의 로딩 상태는 바뀌었으며, 모든 타일과 이미지가 준비된 순간에도 첫 지도 `load`는 발생하지 않은 상태였다.

[SearchMapCanvas](../../frontend/src/features/situationBoard/presentation/components/map/SearchMapCanvas.tsx)는 첫 `map.once('load', ...)`에서 경로 source와 레이어를 만든다. [마커 처리](../../frontend/src/features/situationBoard/presentation/components/map/boardMarkerLayer.ts)는 style이 준비되면 그보다 먼저 source를 만들고 갱신할 수 있다. **이번 초기화 대기 중에는 새 변경분 전달 로직까지 도달하지 못했다.** 이 사실만으로 마커 처리나 새 변경분 코드가 원인이라고 확정하지 않는다.

## 가설 검사와 한계

서버 코드는 바꾸지 않고 시험 탭에서만 아래 호출을 5초씩 바꾼 뒤 자동 복원했다. 이후 기록은 성능 전후 비교에서 제외한다.

| 검사 | 관측 |
|---|---|
| 마커 `setData`를 잠시 보류하고 최신 자료로 복원 | 24호출 보류. 그동안 첫 `load`나 경로 source 생성 없음 |
| 이미 맨 위인 레이어를 다시 올리는 `moveLayer`만 생략 | 36호출 생략. 첫 `load`나 경로 source 생성 없음 |
| 위 두 개입을 함께 적용 | 각각 24·36호출. 역시 초기화되지 않음 |
| 상황판의 화면 갱신 관찰 | 약 5.6초 관찰에서 rAF 카운터 1, 지도 `render` 0. 화면은 visible·focused로 보고됨 |
| 상황판을 떠난 같은 문서의 사건 목록 | 약 5초 동안 rAF 5회. 경로 HTTP 수는 541건에서 더 늘지 않음 |
| 같은 Aside 탭을 제품 코드 없는 `about:blank`로 변경 | 약 5초 동안 rAF 593회. 브라우저 전체의 지속적인 프레임 정지는 아님 |

참고로 별도 로컬 Headless Chrome의 빈 페이지는 5초 동안 rAF 300회였다. 브라우저·화면 주사율·실행 조건이 달라 두 숫자의 비율을 성능 비교로 사용하지 않는다. `about:blank` 이동은 도구의 준비 대기에서 시간 초과가 났지만, 후속 snapshot으로 실제 이동을 확인하고 빈 페이지 검사를 실행했다.

620초 시점에도 경로 source가 없었으나, 스크린샷을 찍은 뒤 확인에서는 source 생성과 경로 전달이 관찰됐다. **한 번의 전후 관찰이므로 캡처가 초기화를 해결했다고 단정하지 않는다.** 반복 재현에서 화면 갱신 예약·브라우저 조건·메인 스레드 작업을 분리해야 한다.

중단 시까지 완료한 경로 조회는 539건, 받은 구간은 42,560개였다. 전체 이력 완료와 첫 경로 렌더링 계측은 없었고 전체 구간 ID 대조도 하지 못했다. 일부 경로 전달이 시작됐다는 사실을 정상 표시·성능 통과로 처리하지 않는다.

## 종료 상태와 다음 확인

브라우저의 임시 호출 변경을 복원하고 계측을 끈 뒤 사건 목록으로 이동했다. 경로 HTTP 기록 수 541건이 두 번의 확인에서 유지돼 조회 중단을 확인했다. 계측을 먼저 껐기 때문에 중단 직전 진행 요청 1건은 수집기의 pending에 남아 있다. 실제 계속 실행 중인 요청으로 해석하지 않는다.

Backend health UP, 새 배포 유지, 경로·구간·GPS fingerprint 일치를 확인했다. API 검증용 임시 토큰 사본은 로컬과 App에서 삭제했다.

다음은 정상적인 화면 갱신이 가능한 조건에서 같은 초기화 지연을 재현하고 원인을 분리하는 것이다. 제품의 초기화 순서를 바꿀지, 계측 브라우저를 바꿀지는 그 결과로 판단한다. 이후 전체 이력·구간 ID·차수/사건 전환을 재검증하고 페이지 한도 비교를 진행한다. 이번 관측은 기존 로컬 20번의 지도 표시 지연 범위에 기록하며 별도 제품 결함으로 중복 등록하지 않는다.

후속 [브라우저 실행 환경 비교](search-path-map-initialization-diagnosis-20261008.md)에서 같은 배포본을 독립 Chrome으로 실행하면 초기화와 첫 경로 렌더링이 진행됨을 확인했다. 이 관측의 10분 이상 대기를 제품 고유 처리 시간으로 사용하지 않는다. 전체 이력 성능 재측정은 남아 있다.
