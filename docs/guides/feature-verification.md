# 기능을 연결해 확인할 검증 흐름

옛 하네스·종료 조건 문서에서 아직 확인할 가치가 있는 흐름만 남겼다. 아래 표는 **테스트 통과 기록이 아니다**. 각 작업에서 필요한 행을 골라 현재 코드·사용자 합의와 대조하고, 실제로 연결한 구간과 대역으로 바꾼 구간을 구분해 검증한다.

## 공통으로 확인할 실패

- 화면에서 버튼을 숨기는 것과 서버에서 잘못된 채널·역할·사건·단말을 거부하는 것을 각각 확인한다. 거부된 요청은 업무 데이터·이벤트를 남기지 않아야 한다.
- 저장 중 중복 실행을 막고, 실패 이유·재시도 가능 여부를 표시하며 입력 초안을 보존한다. 오프라인 저장, 서버 ACK, 수신자의 알림 확인을 같은 성공으로 표시하지 않는다.
- 저장 응답 → 이벤트 저장 → 실제 전송 → REST 재조회 → 화면 표시를 단계별로 확인한다. 적용 대상의 사건·차수·ID·상태·버전이 맞고 오래된 결과가 최신 화면을 덮지 않아야 한다.
- 이벤트 저장 누락, SSE 전송 실패, FCM 실패, 상황판 재조회 지연을 따로 주입한다. 전송 대역의 호출 성공을 실제 수신 성공으로 보고하지 않는다.
- Polygon·LineString·Point의 유효성과 구역 밖 위치를 구분한다. 유효한 경로·마커는 구역 밖이라는 이유만으로 버리지 않는다. 수색 누락·다음 구역·위험도를 자동 판단하지 않는다.
- 종료 후에는 개인정보·위치·사진·재다운로드 주소·재구독이 다시 노출되지 않는지 확인한다. 서버 완료와 오프라인 단말의 삭제 완료를 구분하고, 내부 감사 기록은 사용자 데이터와 섞지 않는다.

## 실행 입력과 증거

공용 값과 로더는 [test-fixtures](../../test-fixtures/README.md)를 사용한다. 테스트별 Java·Kotlin 입력과 실제 mock 112 seed도 유지한다. 외부 타일·S3·FCM을 대역으로 시험했다면 외부 연동은 미검증으로 남긴다.

재시도는 같은 작업의 멱등키·입력을 유지하며 확인한다. 통신 단절 중 로컬 저장·앱 재시작 후 잔존 여부, 복구 후 서버 반영과 화면 갱신을 각각 관찰한다. 실패를 감추려고 행을 지우거나 새 키로 재요청하지 않는다. 대상을 합의하지 않은 서버·단말 초기화도 하지 않는다.

과거의 5초 수집·10초 전송·3초 화면 반영·30분 오프라인·1시간 안정성 수치는 새로 승인한 성능 기준이 아니다. 수집·전송 조건은 [Issue #8](../issues/8-gps-collection-transmission-basis.md)과 [현재 수집 코드의 설명](../features/search-path.md#수집과-전송은-별도-주기)을 기준으로 시험 전에 다시 정한다.

실행 시 커밋·환경·단말·입력·대역 범위, 실제 단절·복구 시간과 원본 로그·화면·DB 결과를 남긴다. 정상 heartbeat처럼 반복 가능한 이벤트를 원본·유형만으로 묶어 중복 오류라고 판단하지 않는다. 중복의 기준과 조회 범위부터 확인한다.

과거 기록은 현재 실행 안내와 분리했다.

- [2026년 5월 시연 준비 테스트](../test-results/demo-test-results-2026-05.md): L1·L3·L5·L6의 대역·고정 입력 검사 결과와 원문. 실제 서버·단말·화면의 전체 흐름 통과가 아니다.
- [Android 네트워크 복구 시험](../test-results/android-network-recovery-2026-05-14/README.md): L4의 부분 결과, Git에 보존한 원본 27개, 미완료 범위와 옛 실행 도구의 복원·주의사항. 판정은 `PARTIAL / NOT FINAL`이다.

과거 명령·판정은 고정 Git 원문으로 보존하며 현재 결과로 고쳐 쓰지 않는다. 단말 사전 점검·증거 수집기는 현재 호출자가 없어 제거했다. 새 시험에서 필요하면 조건·환경·부작용을 합의한 뒤 원문을 참고한다. 문구 검사 통과도 제품 동작의 증거로 사용하지 않는다.

## 과거 문서의 차이와 복원

- 옛 종료 조건은 경로의 주체를 PolicePhone으로 설명했고, 이후 하네스·경계 문서는 계정으로 설명했다. 현재 기록 주체와 개인·공유 계정 정책은 [수색 경로](../features/search-path.md)·[인증](../features/authentication.md)에서 구분한다.
- 경계 문서의 권한표에는 웹 지원 배정이 남아 있지만 같은 문서의 사건 상세는 mock 112 반영만 설명한다. 수색 차수 생성 사유와 `OTHER` 메모 조건도 문서마다 다르다. [사건](../features/incident-lifecycle.md)·[차수](../features/handover.md)의 코드 대조 결과를 확인하며 옛 표를 API 추가 근거로 삼지 않는다.
- 종료 후 재전송 차단·ACK된 기록만 파기한다는 하네스 설명과 마지막 전송을 시도한다는 오프라인 Spec은 충돌한다. [미전송 원본의 처리 조건](../features/offline-sync.md#사건-종료-후-남은-기록)은 후속 합의 대상으로 유지한다.
- Lane 담당자·선행 계약 동결·LGTM 표는 과거 팀 분담이다. 현재 코드 소유권이나 승인자를 추정하는 근거로 쓰지 않는다.

전체 시나리오·수치·식별자·옛 절 번호는 아래 Git 원문에서 복원한다. 코드 주석·당시 시험 기록의 삭제된 문서 경로도 이 원문을 가리킨다.
