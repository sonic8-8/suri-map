# Wireframes — 계약 기준 화면 IA

상태: 3차 (2026-05-10). 각 화면 = IA 명세 + ASCII 박스 wireframe. 폴리폰 P1~P7은 low-fi HTML 1차 산출물로 옮겼다.

## 목적

Hero 3개는 HTML mock(`artifacts/lo/`)으로 정교화. 나머지 화면은 이 문서에 **IA 명세 + ASCII 박스 다이어그램**으로 표현한다. 본 개발 또는 추가 low-fi 생성 전에 이 문서를 먼저 계약 기준으로 정렬한다.

베스트 프랙티스:
- **Hero 3-5개**: 정체성·핵심 패턴 검증을 위한 정교한 HTML mock
- **나머지**: ASCII wireframe + 텍스트 명세
- **재사용**: nonHero 화면은 Hero 패턴 재사용으로 빠르게 구현

## 계약 기준

화면 설계는 다음 기준 문서를 우선한다. 화면 문서와 기준 문서가 충돌하면 화면 문서를 수정한다.

| 관심사 | 기준 |
|---|---|
| Public HTTP URL, request/response, error | `docs/api/api-spec.md` |
| Spec/Lane 소유권, entity/event/slot, channel/role matrix | `docs/spec/boundaries.md` |
| 하네스 SC, fixture ID, e2e red test | `docs/spec/harness-scenarios.md` |
| Spec별 owns/provides/consumes 실행 계약 | `docs/spec/specs/*.json` |
| DB 엔티티·관계·컬럼 의미 | `docs/db-design/db-design-readable.md` |
| 제품 배경과 권한 | `docs/prd.md` |
| Lane/Phase와 산출물 규칙 | `docs/tasks/index.md` |

### Android / Web 경계

| 채널 | 화면 책임 | 쓰기 가능 | 쓰기 금지 |
|---|---|---|---|
| Android 폴리폰 | 현장 입력, 수색 세션, GPS 경로, 마커, 오프라인 기록, 로컬 경고 | 수색 시작/일시정지/재개/종료, 경로 batch, 현장 마커·사진, 오프라인 패키지 상태, heartbeat/FCM token, 인수인계 메모 | 사건 가져오기, 지원 부대 배정, 전체 수색 구역 변경, 구역 분할·할당·완료, 새 OP 생성, 차량·도보 보정, 사건 종료 실행, 상황판 조회 |
| Web 상황판 | 지휘 상황판, 구역/OP/종료 지휘, OP 비교, 요약, 전체 상황 조회 | 사건 가져오기, 구역·OP 지휘 write, 사건 종료, 차량·도보 보정, 인수인계 메모 | 앱 전용 수색 세션, 경로 batch, 현장 마커 생성, 폴리폰 미전송 큐 재전송 |

Android 화면에 Web 지휘 흐름을 넣지 않는다. Web 화면에는 Android 로컬 미전송 큐/로컬 경고 조작을 넣지 않는다.

## W3. 수색 구역 편집 / 분할 / 할당

- **연결 SC**: SC-04, SC-10
- **주 사용자**: 현장 지휘관 (MP_O · SU_O · LP_O). 대원 = readonly
- **IA**: Hero 1 layout 재사용 + 좌측 도구 패널 (그리기/분할/할당) + 중앙 지도 (구역 3계층 편집 가능) + 우측 구역 트리

# 폴리폰 화면 (Hero 2개 + 텍스트 IA)

Android 폴리폰 화면은 현장 입력과 로컬 상태 확인에 집중한다. `수색 중 지도`와 `마커 생성 바텀시트`는 Hero HTML로 이미 다루며, 아래 텍스트 IA는 그 외 화면과 보조 화면을 정의한다.

## P1. 인증 / 폴리폰 접속

- **운영 전제**: 폴리폰은 팀 단위(팀 업무폰) 또는 순찰차 단위(순찰차 업무폰) 1대 지급(PRD §0.1, §8.4)이며, 삼성 Knox 위에서 운영되는 관리 단말이다. 단말 ↔ 팀 계정 또는 순찰차 계정은 1:1 매핑(L5-03-auth-contract.md §4.2 fixture)이고, "팀 계정 또는 순찰차 계정 장기 로그인 유지"가 PRD §8.4와 boundaries.md §S1-2 §282에서 이미 보장되어 있다. 따라서 앱 화면에 ID/PW 또는 바인딩 폼을 노출하지 않는다. 세션 발급·복구는 managed configuration, 장기 세션, 내부 bootstrap을 통해 앱 내부에서 처리한다.
- **연결 SC**: — (인증)
- **주 사용자**: 모든 폴리폰 계정
- **결정**:
  - **정상 운영: 관리 폴리폰 자동 확인**. 앱 실행 시 관리 폴리폰 상태, 내부망 도달, 배정 사건 가용성을 짧은 상태 전환으로 확인한 뒤 사건 선택으로 자동 진입한다.
  - **제외: 앱 ID/PW 로그인 폼**. 세션 만료·복구 상황에서도 사용자가 계정/비밀번호를 입력하는 화면을 두지 않는다. 앱은 내부 세션 bootstrap을 재시도하고 실패하면 IT 문의/재시도 안내만 제공한다.
  - **제외: 바인딩 코드 입력 폼**. 최초 설치·기기 교체·관리 설정 주입은 Knox/EMM/OOBE 운영 절차로 본다. 앱 화면에서는 "관리 설정이 없습니다" 실패 분기로만 표현한다.
  - **제외: 등록 단말 상세 상태판**. 관리 프로필/내부망/등록 상태를 사용자에게 매번 보여주는 화면은 OS/EMM 영역과 중복되어 부적합.
- **핵심 행동**: ① 관리 폴리폰·내부망 자동 확인 ② 성공 시 사건 선택(P2)으로 자동 이동 (배정 0건이면 P2 empty가 처리) ③ 실패 시 사용자 해결/IT 안내 분기
- **상태**: managed_phone_checking · internal_network_ok · not_managed_phone · internal_network_unavailable · server_rejected_phone · managed_config_missing · offline (캐시된 마지막 세션 자동 복구. 실패 시 안내)
- **재사용**:
  - 다크 base (Hero 2·3)
  - 큰 CTA 패턴 (Hero 2·3)
- **신규**:
  - 관리 폴리폰 자동 확인 전환 상태 (3단계 progress)
  - 실패 분기 banner (variant 1~4)
- **제외**:
  - ID/PW 폼 입력
  - 최초 설치/복구용 기기 연결 또는 바인딩 코드 입력 화면
- **권한**: 인증 전 = 누구나 OS 권한 요청. 미등록 폴리폰·미배정 폴리폰은 사건 목록 진입 차단
- **참고**: 폴리폰 사전 설치 가정 (PRD §3.2). 첫 실행 시 OS 권한 (위치·카메라·알림) 요청. 인증 전 화면에는 사건명, OP, 배정 사건을 노출하지 않는다. 개인 단위 식별(Knox Authentication Manager PIN/Face, Knox SSO SDK)은 MVP 범위 외이며 v2 후보다.

## P3. 오프라인 패키지 다운로드

- **연결 SC**: SC-03
- **주 사용자**: 모든 폴리폰 계정 (사건 배정 폴리폰)
- **진입·종료 트리거 (2026-05-11)**:
  - **진입**: P2 사건 카드 탭 → 서버 manifest 변경 체크 → 변경 있으면 P3 자동 진입, 변경 없으면 P3 건너뛰고 P5 직진
  - **종료 (성공)**: 100% + readyForOfflineUse=true → P5(수색 중 지도)로 자동 이동
  - **종료 (부분 성공)**: 타일 미완료(readyForOfflineUse=false) → `제한 안내 후 열기` CTA로 사용자 결정 → P5 이동

- **자동 재시도 정책 (2026-05-11)**: 실패 항목은 WorkManager가 자동 재시도(1초 → 5초 → 30초 backoff, 최대 3회). 사용자 수동 재시도 CTA는 **자동 재시도 한계 도달 시에만 노출**한다. 한계 도달 전에는 chip `자동 재시도 N/3`로 상태만 표시 (P4 진단 화면과 같은 원칙: 자동 처리는 자동으로).

- **핵심 행동**: ① 다운로드 자동 시작 ② 진행률 모니터 ③ 자동 재시도 한계 도달 항목만 수동 조치

## P7. 사건 종료 — P2 다이얼로그로 격하

- **변경 (2026-05-11)**: 단독 화면을 폐기하고 **P2 사건 선택 화면 위 다이얼로그 + 백그라운드 정리**로 격하한다.
- **사유**: 현장 사용자는 "이 사건은 종료됐고 더 이상 입력할 수 없다"만 알면 충분하다. 실종자 정보 제거·좌표 파기·패키지 삭제 진행률은 백그라운드 작업이지 사용자에게 progress bar로 보여줄 가치가 없다 (anti-patterns §6.1 OS 영역 모방).
- **연결 SC**: SC-12
- **현재 동작**:
  - INCIDENT_CLOSED FCM 수신 → 앱은 사건 컨텍스트에서 자동 이탈 → P2 사건 선택 화면으로 자동 이동 → 그 위에 "사건이 종료되었습니다" 다이얼로그 표시
  - 로컬 정리(미전송 ack, 좌표 파기, 패키지 삭제, 컨텍스트 잠금)는 WorkManager로 백그라운드 진행
  - 사용자는 [확인] 1번으로 다이얼로그 종료
- **mock**: `lo-polifon-incident-list-v1.html` 안에 "P7 사건 종료 다이얼로그" variant로 통합. 별도 `lo-polifon-incident-closed-cleanup-v1.html` 파일 삭제됨.
- **참고**: PRD §8.5 정리 정책은 그대로(ack 받은 데이터만, 미전송 항목은 flush 후 삭제). 다만 그 진행을 UI로 보여줄지 여부는 별개이고, 본 라운드에서 "보여주지 않음"으로 결정.
