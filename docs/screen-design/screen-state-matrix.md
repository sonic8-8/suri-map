# 화면 상태를 구분한 이유와 남은 차이

2026-05의 상태 설계를 요약한다. 상태 이름은 당시 화면 표현이지 새 API·DB enum이 아니다. 각 화면에 같은 loading/error 표를 반복하는 대신 공통 구분과 화면별 주의점을 남겼다.

## 공통으로 구분할 상태

| 구분 | 사용자가 알아야 할 것 |
|---|---|
| 기본·불러오는 중·데이터 없음 | 실제로 없는 데이터인지 아직 못 받은 데이터인지. 캐시와 마지막 갱신 시각도 구분 |
| 실패 | 실패한 영역·입력 보존 여부·가능한 재시도. 일부 실패가 지도·원본 조회 전체를 막지 않음 |
| 접근 거부·읽기 전용 | 화면 접근 자체가 거부됐는지 수정만 불가한지, 이유·복귀·문의 방법 |
| 오프라인 | 서버 확인 없이 가능한 로컬 기록과 불가능한 서버 명령을 구분 |
| 일부 미전송·최신성 저하 | 로컬 저장·전송 대기·서버 수신을 구분. 오래된 위치를 최신 위치나 위험 판정으로 표시하지 않음 |
| 충돌 | 최신 서버 상태와 보존한 입력을 구분. 무조건 덮어쓰기라는 정책을 화면 문구로 확정하지 않음 |
| 수색 차수 전환·근무 교대 | 서로 다른 변화. 이전 기록 보존과 현재 입력 대상을 구분 |
| 사건 종료·파기 중 | 새 입력 차단과 실제 데이터 삭제 완료를 구분. 종료 화면에서 개인정보·좌표를 재노출하지 않음 |
| 단순 보기 | 무엇을 숨겼는지 알 수 있어야 하며 원본 데이터를 변경하지 않음 |

구체 권한은 [권한 가정](permission-matrix.md), 문구는 [라벨 기록](screen-labels.md), 기록·전송의 차이는 [오프라인 동기화](../offline-sync.md)를 확인한다.

## 웹 화면별 주의점

| 화면 | 보존할 요구 |
|---|---|
| 로그인 | 접속 중 중복 실행 방지, 네트워크·인증 실패 안내. 옛 자체 ID/PW 폼은 현재 OIDC와 구분 |
| 사건 목록·가져오기 | 빈 배정과 조회 실패 구분, 캐시·마지막 성공 시각 표시, 오프라인 가져오기 차단, 종료 카드는 허용 메타만 |
| 상황판 | 구역이 없어도 지도 표시, 실패한 패널만 재조회, 업무폰별 마지막 갱신 구분. 위치를 그대로 보존할지 종료로 지울지 구분 |
| 구역 편집 | 빈 구역은 그리기 안내, 도형·저장 실패는 초안 유지, 차수·종료·권한·동시 변경 확인 |
| 차수 비교·인수인계 | 선택 차수별 표시, 요약이 없어도 원본·메모 확인, 새 차수 권한과 메모 작성 권한 분리 |
| 마커 상세 | 메타와 사진의 로딩·실패 분리, 타인 마커 읽기와 수정 권한 구분, 삭제·사진 상태 확인 |
| 차량·도보 보정 | 경로 부재 안내, 선택 구간과 변경 결과 구분, 실패 시 기존 값 유지, 동시 변경 확인 |
| 패키지 상태 | 배정 단말 없음·항목별 실패·마지막 보고 구분. 단말의 다운로드 완료를 웹 캐시만으로 단정하지 않음 |
| 종료·파기 | 종료 전 확인·실패 안내, 종료 후 쓰기·재오픈·재구독·재다운로드 금지와 파기 상태 구분 |

지도 초기 범위는 [설계 배경과 코드 차이](../contracts/situation-board-initial-map-plan.md), 종료 후 남은 데이터 문제는 [상황판](../situation-board.md)에서 확인한다.

## 앱 화면별 주의점

| 화면 | 보존할 요구 |
|---|---|
| 접속 확인 | 관리 설정 부재·미관리 단말·내부망 실패·서버 거부 구분. 인증 전 사건 정보 숨김. 배정 0건과 인증 실패를 혼동하지 않음 |
| 사건 선택 | 빈 목록·캐시·계정 거부·종료 안내 구분. 사건 수가 항상 1개라고 단정하지 않음 |
| 패키지 적재 | 변경 없으면 건너뛰기, 필수 데이터와 타일 완료 구분, 실패 항목만 재시도. 제한된 지도 진입을 준비 완료로 표시하지 않음 |
| 수색 지도 | 기록 중·일시정지·종료를 구분. 오프라인 로컬 기록, GPS 약함·마지막 유효 위치, 현재 차수 없음 안내. 미전송 처리와 새 기록은 별도 |
| 마커 입력 | 유형 선택 시 최소 마커 기록, 지원 요청은 세부 종류 선택, 메모·사진 추가 저장을 구분하려던 설계. 실패 시 입력 보존 |
| 미전송 진단 | 정상 자동 전송은 상태 표시로, 사용자 조치가 필요한 처리 불가는 사유·문의 방법으로 표현. 성공하지 않은 원본을 숨기거나 삭제하지 않음 |
| 로컬 경고 | GPS·배터리·지도·통신 조건을 서버 없이 감지하는 요구. 동시 배너가 지도·핵심 행동을 가리지 않는지 확인 |
| 강조 알림 | foreground 배너와 background/잠금 알림 구분, 확인·해당 마커 지도 이동, 발신 업무폰 제외 요구. 권한·종료 상태 재확인, 민감 내용 노출 방지 |
| 마커 상세 | 일부 사진 전송 대기·읽기 전용·삭제 확인 구분. 수정·삭제의 오프라인 허용 범위는 실제 저장·복구와 함께 확인 |
| 이전 근무 확인 | 강제 이동보다 미확인 기록 배너로 안내하려던 설계. 요약의 준비·실패·입력 시각과 원본 표시를 분리 |
| 메모 작성 | 차수·근무 구간과 대상 표시, 초안 보존, 로컬 저장과 서버 수신 구분 |
| 사건 종료 안내 | 사건 선택으로 이동·종료 확인, 쓰기 차단·백그라운드 정리를 제안. 작성 중 초안과 이미 저장한 미전송 원본은 다르게 취급 |

배터리 20%/10%, 경고 상위 2개, 미전송 5/20건, 재시도 1→5→30초·3회는 당시 시안의 수치다. 현재 운영 정책으로 다시 채택하지 않았다. Full-screen intent도 당시 검토 후보였으며 권한·운영 정책을 확인한 구현이 아니다.

## 그대로 구현하면 안 되는 충돌

| 과거 자료의 차이 | 현재 확인할 기준·남은 판단 |
|---|---|
| 앱·웹 요약 생성/재시도 버튼과 조회 전용 설계가 공존 | [인수인계](../handover.md)의 서버 생성·실패 시 원본 확인 요구. 옛 버튼을 자동 복원하지 않음 |
| 대원의 웹 접근을 허용하는 셀과 금지하는 권한표가 공존 | [인증](../authentication.md)의 채널·역할·사건 배정과 실제 Controller·소비자 대조 |
| 웹 구역·구간 보정은 오프라인 저장 차단 / Outbox 적재로 혼재 | 웹 재전송 기능을 문서만으로 새로 만들지 않음. 초안 보존과 서버 저장 정책 별도 합의 |
| 업무폰 미배정이면 접속 차단 / 사건 목록 empty로 혼재 | 미등록·인증 거부와 사건 배정 0건을 구분해 실제 흐름 확인 |
| 종료 시 초안 폐기·모든 기록 거부 / 미전송 ACK 후 파기로 혼재 | [데이터 파기](../data-retention.md)·[동기화](../offline-sync.md). 미전송 원본을 무조건 삭제하지 않음 |
| 마커 위치 수정 불가 / 생성·상세에서 수동 조정 허용 | [마커·사진](../marker-photo.md)의 현재 DTO·앱 동작과 사용 의도 대조 |
| “빈 구역인데 전체 구역 outline 표시”, 모든 종료 데이터 조회 가능 | 구역 부재와 종료 후 허용 메타·민감 데이터 제거를 구분 |
| 같은 5분 기준이 최신성 표시·통신 끊김으로 혼재 | [업무폰 최신성](../authentication.md#통신-최신성과-알림-토큰)의 측정 시각·판정 기준 확인. 현장 허용 지연 아님 |

옛 상황판 슬롯 `toast`는 현재 `marker_notification`과 구분한다. 현재 등록·소비 흐름은 [상황판](../situation-board.md)에 연결돼 있다. 옛 13개 슬롯 표를 복제해 유지하지 않는다.

## 원문과 검증

전체 23개 화면 정의·상태표·2026-05-11 변경은 [정리 전 원문](https://github.com/sonic8-8/suri-map/blob/3cd777752e2178ebb3470e6f749b1521ce404e7a/docs/screen-design/screen-state-matrix.md)에 있다. 빈 칸을 모두 채우거나 시안이 존재한다는 사실은 실제 연결 검증이 아니다. [실기기 QA](artifacts/device-qa/AUI-T14/report.md)도 디버그 상태 표시 범위로 읽는다.
