# 구역 편집 화면의 설계 배경

2026-05-08에 정한 화면 의도와 현재 코드의 차이를 보존한다. 당시 Mock 구현 계획·체크리스트는 완료 기록이 아니다. 구역 도형·배정의 업무 규칙은 [수색 구역](../features/search-area.md), 과거 시안은 [자료 안내](README.md#git에서-찾는-과거-시안)에서 확인한다.

## 남길 의도와 이유

| 당시 선택 | 이유 |
|---|---|
| 전체 수색 구역이 없어도 상황판을 열고, 사용자가 버튼으로 편집 화면에 진입 | 지도 확인과 구역 지정을 분리. 자동 이동으로 사용자의 판단을 대신하지 않음 |
| 전체 구역 저장 뒤 하위 구역 분할·담당 배정을 강제하지 않음 | 전체 범위와 담당 배정은 다른 작업. 담당 구역 없이 시작하는 초동 수색도 고려 |
| 미배정 상태는 닫을 수 있는 안내로 표시 | 상황은 알리되 소규모 수색에 분할을 강제하지 않음 |
| 접근 거부와 읽기 전용을 구분 | 화면을 못 보는 경우와 편집 권한만 없는 경우는 다름. 비활성 이유를 함께 표시 |
| 저장 실패 시 그리던 초안 보존 | 잘못된 도형·통신 실패 때문에 사용자의 입력을 잃지 않음 |
| 오프라인에서는 편집 초안과 서버 저장을 구분 | 로컬 초안을 만들 수 있다는 뜻이지 서버 저장·재전송까지 완료됐다는 뜻은 아님 |

초기 구역이 없을 때는 전체 구역 그리기를 안내하고, 종료 사건에서는 편집을 막는 설계였다. 도구·지도·구역 트리를 함께 두되 구역을 자동 생성하거나 누락을 판정하지 않는다.

## 코드와 다시 확인할 차이

2026-09-21 정적 확인이며 브라우저 조작·API 성공 검증은 하지 않았다.

- [AreaEditPage](../../frontend/src/features/areaEdit/presentation/pages/AreaEditPage.tsx)에 조회·그리기·저장 흐름이 있다. 원문의 “지도 그리기·저장 API는 향후 연결”을 현재 상태로 복사하지 않는다.
- 저장 활성 조건은 현재 차수·종료 상태와 작성한 구역 도형 등을 확인한다. 전체 구역만 저장할 수 있는지, 하위 분할·담당 배정을 언제 요구하는지는 실제 저장 흐름으로 확인한다.
- 원문은 “담당 구역 없는 업무폰 수”를 안내하려 했다. 현재 `unassignedAreaCount`는 `geometryState=pending` 구역 중 완성된 도형 초안이 없는 수이며, 이를 [AreaHierarchyPanel](../../frontend/src/features/areaEdit/presentation/components/AreaHierarchyPanel.tsx)의 `unassignedPhoneCount`에 전달한다. 업무폰 수·도형 미완성 수·담당 미배정 수를 혼동할 수 있어 [이름 정리 후보](../refactoring/codebase-naming-candidates.md)에 등록했다.
- 화면의 권한·오프라인 분기와 실제 서버 거부는 별도로 대조한다. Mock 상태를 바꿔 보였다는 것만으로 권한 검증을 마쳤다고 판단하지 않는다.
