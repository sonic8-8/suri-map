# UI 라벨 표기 규칙

상태: 초안. 이 문서는 Suri-Map의 화면 라벨·마이크로카피·용어 표기 규칙을 정한다.

## 목적

- 화면마다 같은 도메인 객체가 다른 단어로 표기되지 않게 한다.
- KRDS의 공공·격식 톤과 Suri-Map 운영 도구 톤을 정렬한다.
- 디자이너·구현자·AI 프로토타입 도구가 일관된 라벨을 쓰게 한다.

## PRD 도메인 용어와의 관계

- **PRD §0.1**: 도메인 정의 (이 객체는 무엇인가)
- **이 문서**: UI 라벨 표기 (화면에서 어떻게 부르는가)
- 도메인 정의는 PRD가 진실의 원천이다. 이 문서는 그것을 바꾸지 않고 **표기 규칙**만 추가한다.

도메인 정의가 바뀌면 PRD를 먼저 수정하고 이 문서를 동기화한다.

## 1. 표기 규칙 (Tone & Voice)

### 1.1 톤

- **격식 + 간결**. KRDS 공공 톤을 base로 한다.
- 어미: `-합니다`, `-됩니다` 기본. 단, 버튼·라벨은 명사형 또는 동사 단축형 (`수색 시작`, `마커 생성`, `사건 종료`).
- 친근한 표현 (`-해요`, `~할게요`) 사용 금지.
- 영어 음차어 최소화. 단, 도메인 표준 용어(예: `OP`, `GPS`, `FCM`)는 허용.

### 1.2 표기 일관성

- 한글 + 한자/영문 혼용 시 영문은 한글 뒤 괄호: `수색 차수(OP)`
- 숫자: 아라비아 숫자 기본. `1차`, `2차` 등 차수 표기.
- 시각: `HH:mm` (예: `13:52`). 초 표시는 필요한 화면만.
- 좌표: 사용자 화면에 노출 시 소수점 5자리. 내부 ID와 분리.
- 경과 시간: `12분 전`, `1시간 전` (한국어 상대 시간).

### 1.3 강조어 금지

- "위험", "경고", "긴급" 단어는 PRD에서 정의된 알림(지원 요청·실종자 발견·동기화 실패)에만 사용.
- 추측·판단 단어 금지: `~로 보입니다`, `~할 것으로 예상`, `추천`, `최적`.

## 5. 알림 / 토스트 표기

### 5.1 강조 알림 (PERSON_FOUND, SUPPORT_REQUEST)

- **실종자 발견**: `실종자 발견 — [위치] / [작성 계정]`
- **지원 요청**: `지원 요청 — [요청 종류] / [위치]`
- 강조 색·소리 사용. dismiss는 명시적 액션.

### 5.2 일반 알림

- 단순 진술. `~되었습니다` / `~합니다`.
- 자동 dismiss 허용. 단, 무전 응대 중 놓칠 위험 있는 알림은 §6 anti-pattern 6.1 참조.

## 6. 빈 화면 (empty state) 카피

각 화면의 empty state 메시지는 `screen-state-matrix.md`의 셀에 정의한다. 공통 톤:

- 1행: 사실 진술 (`진행 중인 사건이 없습니다`)
- 2행: 다음 액션 안내 (`실종팀 지휘 계정으로 사건을 가져오면 이곳에 표시됩니다`)
- 추측·격려 표현 금지

## 7. 변경 시 영향

- 도메인 객체 표기 변경 → 모든 화면 산출물 영향. 필수 검토 대상: `screen-state-matrix.md`, `dense-tokens.md` (라벨 길이 변경 시 토큰 영향)
- PRD §0.1 도메인 용어 변경 → 이 문서 §2 동기화 우선
