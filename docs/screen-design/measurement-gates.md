# 측정 검증 게이트

상태: 초안. 이 문서는 화면 설계 결과물이 정성적 "괜찮아 보임"이 아니라 정량 기준으로 검수될 수 있게 한다.

## 목적

- 화면 리뷰 reject 기준을 객관화한다.
- field-context.md의 환경 가정과 dense-tokens.md의 정보 밀도 목표가 실제로 달성되는지 측정한다.
- 프로토타입 → 실 구현 사이의 회귀를 막는다.

## 사용 방법

- 화면 high-fi 단계에서 게이트별 측정값을 채운다.
- 미달 → reject + 재작업.
- 측정 불가능한 게이트는 게이트로 두지 않는다 (정성 리뷰는 별도).

## 게이트 분류

- **G1**: 정보 밀도
- **G2**: 가독성·접근성
- **G3**: 인지 부하·태스크 효율
- **G4**: 환경 견고성
- **G5**: 상태 완전성
- **G6**: 금지 행동 누설

각 게이트는 측정 방법·기준값·검증 시점을 명시한다.

## G1. 정보 밀도

### G1-1. 상황판 폴리폰 동시 식별

- **측정**: 1920×1080 상황판 default 화면에서 지도 zoom 기본값으로 **폴리폰** 위치·상태(online/stale/lost)·라벨이 한눈에 식별 가능한 폴리폰 수 (1팀 = 1폴리폰)
- **기준 (1차 산정)**: 약 12~15대 편안한 식별 / 20대 초과 시 cluster (dense-tokens §1.1)
- **시점**: high-fi 화면 완성 시
- **방법**: 5초 글랜스 후 화면 가리고 식별한 폴리폰 수 회상
- **검증 필요**: 광주 외 지역·규모는 user-research-source.md §3.1.1로 확장

### G1-2. 상황판 마커 동시 식별

- **측정**: 같은 조건에서 마커 유형·위치를 식별 가능한 마커 수
- **기준 (1차 산정)**: 40개 이상 (dense-tokens §1.1)
- **시점**: high-fi 화면 완성 시

### G1-3. OP 동시 overlay 시각 한계

- **측정**: OP 비교 화면(FR-11)에서 사용자가 N개 OP를 선택해 overlay했을 때, 어느 N부터 색·dash·opacity 인코딩 한계로 가독성을 잃는지
- **기준 (1차 산정)**: 5차까지는 식별 가능. 6차+ 선택 시 사용자에게 가독성 경고 표시 (dense-tokens §1.1)
- **시점**: 프로토타입 완성 시
- **방법**: 1·2·3·5·7·10차 시뮬레이션 후 사용자 회상 테스트
- **주의**:
  - OP 누적 차수 자체는 상한 없음 (재수색은 실종자 발견 시까지 계속 — FR-12).
  - OP 비교는 재수색·범위 변경 비교다. 인수인계 비교가 아님 (인수인계는 DutyShift). G6-7 참조.
  - 사용자가 N개 OP 선택은 **사용자 권한**이며 시스템이 N개 이상을 막지 않는다. 가독성 경고만 표시.

### G1-5. 사건 동시 운영 표시

- **측정**: 다중 사건 운영(실종팀 지휘 계정)에서 한 화면에 표시 가능한 활성 사건 수
- **기준 (1차 산정)**: 3건 (광주 실종팀 1명 모니터링 추정 — dense-tokens §1.1)
- **시점**: high-fi 완성 시
- **검증 필요**: 광주 외 지역·실 운영에서 동시 사건 수 확인

### G1-4. 폴리폰 지도 점유율

- **측정**: 지도 + 바텀시트(닫힌 상태/펼친 상태) 시 지도 픽셀 점유율
- **기준**: dense-tokens §1.2의 X%
- **시점**: 폴리폰 화면 완성 시

## G2. 가독성 / 접근성

### G2-1. 본문 contrast (WCAG)

- **측정**: 모든 본문·라벨의 텍스트 vs 배경 contrast
- **기준**:
  - 웹 상황판: WCAG AA 4.5:1 이상
  - 폴리폰 (야외 가시성): WCAG AAA 7:1 이상 (field-context §1.1)
- **시점**: 토큰 결정 직후
- **방법**: 자동화 도구 (axe, Lighthouse) + 수동 검증

### G2-2. 색맹 식별

- **측정**: 차량/도보/구역/마커/상태 색이 색맹 시뮬레이션에서 구분되는지
- **기준**: Deuteranopia·Protanopia·Tritanopia 3종 시뮬레이션 모두 통과
- **시점**: 토큰 결정 직후
- **방법**: Color Oracle 또는 동등 도구. 색 + 패턴/아이콘/라벨 동시 인코딩 확인 (anti-patterns §3.1)

### G2-3. 화면 zoom 200%

- **측정**: 웹 상황판을 브라우저 zoom 200%에서 layout 깨지지 않고 사용 가능
- **기준**: 좌측·중앙·우측 패널 모두 접근 가능, 가로 스크롤 없이 핵심 정보 식별
- **시점**: high-fi 완성 시

### G2-4. 폴리폰 야외 가독성

- **측정**: 야외 직사광선(50,000 lux 시뮬레이션 또는 실제) 환경에서 본문 식별
- **기준**: 1m 거리에서 본문 텍스트 식별 가능
- **시점**: 토큰 결정 후 실 폴리폰 검증
- **방법**: 야외 또는 고휘도 디스플레이 + 강한 조명

### G2-5. 키보드 접근성 (웹)

- **측정**: 마우스 없이 키보드만으로 모든 핵심 액션 도달 가능
- **기준**: Tab 순서 논리적, focus indicator 명확
- **시점**: high-fi 완성 시

### G2-6. 지도 위 텍스트 가독성

- **측정**: 지도 베이스맵(주간/야간/위성) × 우리 라벨 contrast
- **기준**: 모든 베이스맵 조합에서 WCAG AA 통과 (halo/배경 칩 사용 가능)
- **시점**: 지도 스타일 확정 직후

## G3. 인지 부하 / 태스크 효율

### G3-1. 마커 생성 탭 수

- **측정**: 폴리폰 사건 진입 → 마커 1개 생성 완료까지 탭 수
- **기준**: 결정 필요 (3탭 이내 권장)
- **시점**: 프로토타입 완성 시
- **방법**: 사용자 테스트 또는 클릭 path 분석

### G3-2. 폴리폰 stale 식별 시간

- **측정**: 상황판에서 stale 상태 폴리폰을 식별하기까지 소요 시간
- **기준**: 5초 이내
- **시점**: 사용자 테스트 시

### G3-3. OP 차이점 인식 시간

- **측정**: OP 비교 화면에서 두 OP의 주요 차이(완료 구역·새 마커)를 인식하기까지 시간
- **기준**: 10초 이내
- **시점**: 사용자 테스트 시

### G3-4. 사건 전환 시간

- **측정**: 다중 사건 운영 시 사건 A → 사건 B 전환 후 컨텍스트 파악
- **기준**: 5초 이내. 페이지 reload 금지 (anti-patterns §5.1)
- **시점**: 프로토타입 완성 시

### G3-5. primary CTA thumb zone 도달

- **측정**: 폴리폰 모든 화면의 primary CTA가 한 손 엄지 도달 영역 안에 있는지
- **기준**: 100%
- **시점**: 화면 설계 시
- **방법**: thumb zone 오버레이로 시각 검증

## G4. 환경 견고성

### G4-1. 장갑 터치 정확도

- **측정**: 방한 장갑 착용 후 마커 생성·구역 선택 정확도
- **기준**: 결정 필요 (90% 이상 권장)
- **시점**: 실 폴리폰 검증 시
- **방법**: 사용자 테스트

### G4-2. 오프라인 표출

- **측정**: 모든 폴리폰 화면에서 오프라인 상태가 1초 이내 인지 가능
- **기준**: 모든 화면 통과 (anti-patterns §4.5)
- **시점**: 프로토타입 완성 시

### G4-3. 미전송 큐 임계 변경

- **측정**: 미전송 N건 초과 시 시각 강조 발생
- **기준**: dense-tokens §1.2의 N건 임계 적용
- **시점**: 프로토타입 완성 시

### G4-4. destructive action confirm

- **측정**: 파괴적 액션(수색 종료·사건 종료·구역 삭제)에 큰 confirm dialog 또는 검증된 hold-to-confirm progress ring이 있는지. 500ms 수준의 짧은 long-press 단독 confirm은 실패로 판정.
- **기준**: 모든 destructive action 통과. undo window는 서버/도메인에서 되돌릴 수 있는 액션에만 인정
- **시점**: 화면 설계 시

## G6. 금지 행동 누설

### G6-1. anti-pattern 검수

- **측정**: anti-patterns.md §1~§6의 모든 anti-pattern이 화면에 없는지
- **기준**: 0건 검출
- **시점**: 프로토타입·high-fi 완성 시
- **방법**: 체크리스트 기반 수동 리뷰

### G6-2. AI 요약 guard

- **측정**: search_history_summary 표출에서 추측·지시·위험도 표현 없는지
- **기준**: 0건 (ADR-0034)
- **시점**: 요약 표출 화면 완성 시

### G6-3. 자동 누락 시각화 없음

- **측정**: 빈 영역에 hatch·빨간 패턴·"미확인" 라벨 자동 부여 없음
- **기준**: 0건 (anti-patterns §1.1)
- **시점**: 지도 화면 완성 시

### G6-4. 길찾기·검색·즐겨찾기 패턴 없음

- **측정**: 네이버 지도식 검색바·POI 카드·즐겨찾기 별 아이콘·길찾기 UI 없음
- **기준**: 0건 (anti-patterns §2)
- **시점**: 프로토타입 완성 시

### G6-5. 도메인 모델 정합성

- **측정**: anti-patterns §1.6 (도메인 모델 오해)의 모든 항목이 화면에 없는지
- **기준**: 0건
- **시점**: low-fi/high-fi/프로토타입 모든 단계
- **세부**: 다음 7개 항목 각각 0건
  - G6-5-1 OP를 인수인계/시프트 단위로 표시 (§1.6.1)
  - G6-5-2 폴리폰 수 = 인원 수 표현 (§1.6.2)
  - G6-5-3 마커 생성 권한이 일부 계정으로 제한됨 (§1.6.3)
  - G6-5-4 폴리폰에 웹 상황판 화면 노출 (§1.6.4)
  - G6-5-5 동시 활성 OP 여러 개 (§1.6.5)
  - G6-5-6 지원 부서 간부에 사건 가져오기 CTA (§1.6.6)
  - G6-5-7 사건 재오픈 UI 노출 (§1.6.7)

### G6-6. 권한 매트릭스 정렬

- **측정**: 각 화면의 액션 가시성·활성화가 PRD §8.4 권한 매트릭스와 정렬
- **기준**: 6개 계정 유형 × 14개 동작에 대해 unauthorized 액션 노출 0건
- **시점**: high-fi 완성 시
- **방법**: 계정 유형별 화면 시뮬레이션

### G6-7. OP vs DutyShift 의미 분리

- **측정**: OP와 DutyShift가 화면에서 다른 의미·다른 시각·다른 라벨로 표현
- **기준**: OP 라벨에 인수인계/교대 표현 0건, DutyShift 라벨에 차수/재수색 표현 0건
- **시점**: 화면 라벨 결정 시 + high-fi 완성 시
- **참고**: screen-labels.md §2 OperationalPeriod/DutyShift 라벨 행
