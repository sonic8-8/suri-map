# 사용자 조사 자료와 미확인 가정

현장 가정의 근거를 찾을 때 확인한다. 인터뷰를 직접 읽어 확인한 사실과 문서에서 재인용한 내용을 구분한다. 옛 “MVP 기준 고정·새 인터뷰는 v2 이후에만 반영” 규칙은 현재 작업 방식으로 사용하지 않는다.

## 기록된 출처

| 일자·자료 | 현재 확인 범위 |
|---|---|
| 2026-04-24 경찰 대면 인터뷰 | 옛 PRD가 `2026-04-24_police_in_person_interview.md`를 인용했다. 저장소에서 원본을 찾지 못했으며 외부 보관 위치·대상 소속·동의 여부는 미확인 |
| 2026-04-15 요구사항 정의 | 옛 PRD가 `2026-04-15_requirements_definition.md`를 인용했다. 저장소에서 원본을 찾지 못했으며 외부 보관 여부는 미확인 |

원문 부재를 인터뷰를 하지 않았다는 뜻으로 해석하지 않는다. 반대로 재인용만 보고 직접 확인한 사용자 조사라고 보고하지 않는다.

## 가정의 출처 구분

- 사용자 진술: 광주 실종팀 인원·지원 부대 업무폰 대수 등 당시 전달된 값
- 제품 요구: 앱·웹의 역할, 수색 차수와 근무 교대, 공유 업무폰 운용 등의 요구
- 설계 추정: 화면 정보 밀도, 패널 폭, 묶음 표시, 터치 영역·대비 목표
- 시연 가정: 직접 자료가 없는 상태에서 시안을 만들기 위해 정한 수치

수치와 한계는 [현장 가정](field-context.md)에 모았다. 문서에 숫자가 있다는 이유만으로 현장 검증값·운영 기준으로 채택하지 않는다.

## 후속 조사에서 확인할 내용

| 주제 | 남은 질문 |
|---|---|
| 현장 조작 | 야외·장갑·무전·한 손 입력, 야간·색 구분, 팀원 간 업무폰 공유는 어떻게 이뤄지는가? |
| 운영 규모 | 팀·순찰차·지원 부대 업무폰 수, 여러 사건 전환, 지역별 규모 차이는 어느 정도인가? |
| 인수인계 | 교대 시점과 확인 순서, 수색 차수 변경 사유, 동시에 비교할 이력은 무엇인가? |
| 기록·통신 | 마커 생성 빈도·유형, 오프라인 지속 시간·미전송 누적, 차량 동승자 입력은 어떤가? |
| 다른 업무와 연결 | 112·실종프로파일링과 화면을 얼마나 전환하며 어떤 운영 기록이 필요한가? |

새 자료에는 일자·수집 방식·대상 범위·동의/익명화, 직접 관찰과 해석, 영향을 받는 요구·후속 질문을 짧게 남긴다. 소수 인터뷰를 전체 경찰 업무의 일반적인 사실로 확대하지 않는다. 원본 확보 여부와 추가 조사 가능성은 아직 확인할 대상이다.

과거 참고 목록·기록 양식은 [정리 전 원문](https://github.com/sonic8-8/suri-map/blob/3cd777752e2178ebb3470e6f749b1521ce404e7a/docs/screen-design/user-research-source.md)에 있다.
