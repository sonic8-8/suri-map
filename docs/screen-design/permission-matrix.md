# 화면 권한 설계의 가정

2026-05의 화면·행동별 권한 의도를 요약한다. 이 표는 서버의 실제 권한 검사를 보증하지 않는다. 계정 모델·채널·배정 검사의 현재 차이는 [인증](../features/authentication.md), 마커 작성자 판정은 [마커·사진](../features/marker-photo.md)에서 확인한다.

## 당시 역할 표기

| 약어 | 당시 의미 | 웹 사용 가정 |
|---|---|---|
| MP_O | 실종팀 간부 | 가능 |
| MP_M | 실종팀 대원 | 가능 |
| SU_O | 지원 부서 간부 | 가능 |
| SU_M | 지원 부서 대원 | 앱 전용 |
| LP_O | 지구대/파출소 팀장·당직자 | 가능 |
| LP_M | 지구대/파출소 경찰관 | 앱 전용 |

팀·순찰차·지휘 계정 형태와 단말 등록은 역할 표와 다른 개념이다. 이 약어를 새 API role로 만들지 않는다.

## 화면에서 나누려던 행동

모든 행동에 유효한 인증·채널·사건 접근이 전제된다.

| 행동 | 당시 허용 의도 |
|---|---|
| 배정 사건·지도·마커·사진·패키지 상태 조회 | 채널 사용이 가능한 사건 배정 계정 |
| 사건 가져오기 | Web의 MP_O·LP_O. SU_O는 제외 |
| 전체 구역 지정·분할·담당 배정·완료 | Web의 MP_O·SU_O·LP_O |
| 새 수색 차수·차량/도보 보정 | Web의 MP_O·SU_O·LP_O. 조회와 변경을 구분 |
| 사건 종료 | Web의 MP_O만. 재오픈 버튼 없음 |
| 앱 경로 기록·현장 마커 생성·사진 첨부 | 배정된 업무폰 계정. 간부만 마커를 만들게 제한하지 않음 |
| 마커 수정·삭제 | 지휘 권한자는 사건 내 대상, 일반 계정은 자기 계정 생성분. 앱·웹 소비 API 별도 확인 |
| 초기 기준 마커 추가·수정 | 옛 표는 지휘자를 허용했으나 현재 원천 가져오기·현장 마커와 다른 흐름이므로 별도 확인 |
| 인수인계 메모 작성·수색 이력 요약 조회 | 사건 배정 계정. 요약 생성·재시도는 현재 UI 기능으로 복원하지 않음 |
| 미전송 진단·로컬 경고 | 자기 업무폰의 상태. 다른 폰의 큐를 조작하는 권한이 아님 |
| 종료·파기 상태 확인 | 허용된 비식별 메타만. 조회 가능과 개인정보·좌표 보존을 혼동하지 않음 |

## 거부와 읽기 전용

- 사건 접근이 없거나 채널이 맞지 않으면 진입 거부 이유와 복귀 방법을 보여준다. 일반적인 빈 목록과 구분한다.
- 조회는 가능하고 변경만 불가하면 읽기 전용으로 보여주고 비활성 사유를 가까이 표시한다. Web은 hover/focus 설명을 쓸 수 있지만 앱에서 길게 누르기만으로 사유를 알게 하지 않는다.
- 화면에서 버튼을 숨겼어도 서버에서 다시 검증해야 한다. 서버 오류의 값·HTTP 상태는 이 문서에서 새로 정의하지 않는다.
- 사건 목록은 서버가 접근 가능한 사건만 반환해야 한다는 요구였다. 클라이언트 필터만으로 접근 제어를 대신하지 않는다.
- 실종팀에 인계했다고 기존 지구대/파출소의 사건 접근을 자동 박탈하지 않는 요구를 남긴다. 이전 차수의 보존·현재 차수 편집과 권한 유지도 서로 다르다.

## 충돌과 원문

미배정 단말의 접속 차단/빈 목록, 대원의 웹 접근, 요약 재시도 허용은 옛 문서끼리 달랐다. [충돌 목록](screen-state-matrix.md#그대로-구현하면-안-되는-충돌)을 확인하고 필요한 변경을 사용자와 합의한다.

6개 역할별 상세 표·서버 거부 문구·당시 결정 이유는 [정리 전 원문](https://github.com/sonic8-8/suri-map/blob/3cd777752e2178ebb3470e6f749b1521ce404e7a/docs/screen-design/permission-matrix.md)에 있다. 이번 정리는 권한 변경·접근 제어 검증이 아니다.
