# 권한 × 화면 매트릭스

상태: 초안. 이 문서는 PRD §8.4 권한 매트릭스(6 계정 유형 × 14 동작)를 화면별 액션 가시성·활성화로 매핑한다.

## 목적

- 화면마다 어느 계정에게 어느 액션을 노출할지 명시한다.
- anti-patterns §1.6.3, §1.6.6의 권한 위반(마커 생성을 제한, 지원 부서 간부에 사건 가져오기 등)을 사전에 막는다.
- measurement-gates G6-6 (권한 매트릭스 정렬)의 검수 기준이 된다.

## 출처

- PRD §8.4 권한 매트릭스 (원본)
- ADR-0026 지휘 권한과 채널별 조작 경계 v3
- ADR-0031 MVP 계정 모델

## 3. 화면 진입 자체 차단 vs disabled

### 3.1 진입 자체 차단 (`permission_denied` 상태)

다음 경우는 화면 진입 자체를 막는다.

- 사건 배정이 없는 계정의 사건 상세 진입 (모든 화면)
- 채널 위반 (예: 폴리폰에서 웹 상황판 URL 직접 접근 — PRD §8.8)
- 종료된 사건의 일부 쓰기 화면 (구역 편집 등 — `incident_closed` 상태로 차단)

### 3.2 진입은 허용하되 액션 disabled (`permission_partial` 상태)

다음 경우는 화면은 보여주되 액션만 비활성화한다.

- MP_M(실종팀 대원)의 구역 편집 화면 readonly 조회
- 자기 계정 생성분이 아닌 마커의 수정·삭제 버튼 비활성화 (대원 계정)
- LP_M(지구대 일반)의 OP 비교 화면에서 `새 OP 열기` 버튼 비활성화

## 4. 운영 사건 (서버 거부)

화면에서 차단했어도 서버는 별도로 검증한다 (boundaries.md auth/role guard). 화면이 거부 사유를 어떻게 표출할지:

| 서버 응답 | 화면 표출 |
|---|---|
| `403 channel_not_allowed` | "이 화면은 데스크톱 전용입니다 / 폴리폰 앱에서 시도하세요" |
| `403 role_denied` | "이 동작에는 [필요 역할] 권한이 필요합니다" |
| `403 team_not_assigned` | "이 사건에 배정되지 않았습니다" |
| `403 police_phone_not_registered` | "폴리폰 등록 후 사용 가능합니다" |
| `403 police_phone_not_assigned` | "이 사건에 배정된 폴리폰이 아닙니다" |

## 6. 결정 사항 (1차)

### 6.1 `permission_partial` 안내 방식

- **결정**: 화면 진입은 허용, 비활성 액션 옆이나 아래에 사유를 명시한다. Web은 hover/focus tooltip을 함께 쓸 수 있고, 폴리폰은 long-press tooltip에 의존하지 않는다.
- **카피 패턴**: "지휘 권한이 필요합니다" / "본인이 생성한 마커만 수정·삭제 가능합니다" / "이 사건에 배정되지 않았습니다"
- **anti-patterns §6.3 충돌 회피**: `permission_partial`은 빈 화면이 아니라 **읽기 전용 + tooltip**. `permission_denied`(빈 화면+안내)와 명확히 구분.
- **폴리폰에서 적용 케이스**: 마커 상세에서 자기 계정 생성분이 아닌 마커 → 메타·사진은 보이고 `수정`·`삭제` 버튼 disabled + 버튼 아래 사유 문구 표시.

### 6.2 다중 사건 운영 시 사건 목록 권한 분기

- **결정**: 사건 목록은 `incident_assignment` 기준으로 서버에서 필터링된 사건만 반환. 클라이언트는 추가 필터 안 함.
- **실종팀 지휘 계정 다중 사건**: 본인이 배정된 사건 모두 표시. 다른 사건은 목록에 없음.
- **시각**: 사건 카드에 `내가 가져온 사건` 배지(MP_O가 직접 가져온 경우) vs `참여 중` 배지(다른 계정이 가져왔으나 본인 배정).
- **사건 전환**: 탭 또는 사이드 panel로 즉시 전환 (anti-patterns §5.1 페이지 reload 금지).
- **동시 모니터링 표시 한계**: dense-tokens §1.1의 3건 (광주 추정).

### 6.3 사건 인계 후 지구대/파출소 계정의 OP1 readonly 정책

- **결정**: 인계 후에도 지구대/파출소 계정은 사건 접근 권한 유지 (PRD SC-02 then 1, harness "실종팀 인계 후에도 지구대/파출소 팀 계정·순찰차 계정의 기존 사건 접근 권한은 유지된다").
- **OP1 데이터**: readonly 아님. 새 OP가 열렸으면 LP_O는 새 OP에서 액션 가능 (구역 완료·OP 생성 권한 유지). OP1은 자동으로 비활성 OP가 되지만 권한이 박탈되는 것은 아님.
- **OP 비교 화면**: LP_O는 자기가 작성한 OP1 메모/마커를 같은 사건의 다른 계정 OP들과 함께 overlay 가능.
- **시각**: LP_O가 작성한 마커·메모는 인계 후에도 작성 계정 라벨 그대로 유지.

### 6.4 미배정 PolicePhone 접속 시

- **결정**: 앱 내부 세션 bootstrap 자체는 통과할 수 있으나, 사건 선택 진입 전 접속 확인 단계에서 "이 폴리폰은 사건에 배정되지 않았습니다" 표시 + IT 부서 문의 안내.
- **사건 목록 진입 차단**: 폴리폰 미배정 상태에서는 사건 목록 화면 자체를 잠금. 접속 확인 → 폴리폰 미배정 안내 화면 → 강제 종료 또는 재시도.
- **이유**: 사건 배정이 폴리폰 단위 (PRD §8.4 SC-03 red test "미등록 PolicePhone이 manifest 조회 또는 패키지 적재 상태 보고를 호출하면 `403 police_phone_not_registered`").
- **대응 흐름**: IT 부서가 폴리폰 등록 → 자동으로 사건 목록 접근 가능.
