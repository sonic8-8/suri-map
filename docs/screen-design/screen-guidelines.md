# 화면 표현의 의도와 확인 항목

라벨·토큰·혼동 사례·검증표를 함께 읽어야 했던 내용을 묶었다. 아래는 기존 설계에서 남길 의도이며 새로운 API·권한·수치 기준을 확정하는 문서가 아니다. 화면별 요구는 [화면 상태](screen-state-matrix.md), 현장 가정과 숫자의 출처는 [field-context.md](field-context.md)를 따른다.

## 라벨이 구분해야 할 의미

설명은 짧은 사실과 다음 행동으로 쓰고, 버튼은 `수색 시작`·`사건 종료`처럼 대상을 드러낸다. 안내는 `-합니다/-됩니다`, 숫자는 아라비아 숫자로 쓴다는 기존 원칙을 유지한다. 내부 ID·영어 코드를 업무 용어 대신 노출하지 않는다.

| 의미 | 기존 표기·표현 의도 |
|---|---|
| Incident / MissingPerson | 사건 / 실종자 |
| OperationalPeriod / DutyShift | 수색 차수(OP) / 근무 구간·근무 인계. 차수와 교대를 구분하며 현장 용어·OP 약어 노출 범위는 확인 대상 |
| PolicePhone / Account | 업무폰 / 계정. 옛 “폴리폰·팀 폴리폰” 표기와 제품 표기는 화면 작업에서 정하며 폰 수를 인원 수로 바꾸지 않음 |
| SearchArea / SearchPath | 전체·부대·팀 수색 구역 / 수색 경로. 구역의 계층·담당과 차량·도보·미분류 경로를 구분 |
| 마커 / 지원 요청 종류 | 단서·실종자 발견·지형·지원 요청·운영 메모 / 드론·경찰견·기타 지원. 상위 유형과 세부 종류를 구분 |
| HandoverMemo / SearchHistorySummary | 인수인계 메모 / 수색 이력 요약. 운영 메모·원본·확정 판단과 구분 |
| 불러오는 중 / 데이터 없음 | 아직 못 받은 상태와 실제 빈 배정을 구분 |
| 로컬 저장 / 전송 대기 / 서버 수신 | 실제 저장 성공 뒤 “오프라인 저장됨”, 서버가 받기 전에는 “완료”로 표시하지 않음 |
| 오래된 위치 | 마지막 갱신·경과 시각을 표시. 통신 최신성을 위험 판단이나 복구 목표로 바꾸지 않음 |
| 접근 거부 / 읽기 전용 / 실패 | 진입 불가·변경 불가·실패한 영역과 이유, 입력 보존·재시도 방법을 구분 |
| 패키지 준비 / 부분 실패 | 제한된 지도 진입을 준비 완료로 표시하지 않음. 실패 항목만 재시도하는지 안내 |
| 사건 종료 / 데이터 파기 | 새 입력 차단과 실제 삭제 완료를 구분. 허용된 종료 메타만 표시 |
| 강조 알림 | 발견·지원 요청의 종류·위치·작성 맥락, 확인·해당 위치로 이동할 행동을 제공 |

수색 조작은 시작·일시정지·재개·종료, 지휘 조작은 가져오기·구역 분할/할당/완료·새 차수·사건 종료로 구분한다. OP 사유는 초기·재수색·범위 변경·기타였으며 실제 입력 요구와 대조한다. `HH:mm`·상대 시각·좌표 소수 5자리는 과거 표시 가정이다. 시간대·날짜·[마커 기록 시각](../../CONTEXT.md)은 실제 용도에 맞춘다.

## 배치·색·조작을 선택한 이유

| 남길 의도 | 이유·확인할 점 |
|---|---|
| Web은 비교·조회, 앱은 현장 한 손 입력에 맞춘 배치 | 시민 포털의 큰 카드·검색창·장소 리뷰·길찾기를 그대로 가져오면 지도와 핵심 행동이 밀림 |
| Web의 밝고 조밀한 화면, 앱의 어두운 배경·큰 행동 | 당시 환경 가정에 따른 선택. 다크 모드 자체가 야외 가독성을 보장하지는 않음 |
| 행동과 상태의 색 의미 분리 | 경찰 블루는 핵심 행동, 초록은 기록·동기화라는 기존 의도. 색만으로 상태를 구분하지 않음 |
| 배경색과 글자·아이콘 색 분리 | 어두운 배경에 버튼 배경용 파랑을 글자로 그대로 쓰지 않도록 한 설계 |
| 지도 레이어의 선·면·형태·라벨 구분 | 전체 구역·하위 구역·경로·강조 마커·자기 업무폰이 겹쳐도 읽을 수 있어야 함. 글자는 배경·외곽선으로 보조 |
| 같은 위치의 마커가 있음을 표시 | 마지막 마커 하나만 남기지 않고 묶음 수·펼침 등을 검토. 강조 알림이 가려지는지도 확인 |
| 필터·단순 보기와 원본을 분리 | 무엇을 숨겼는지 알 수 있어야 하며 표시 변경이 원본 데이터를 바꾸지 않아야 함 |
| 큰 터치 영역·간격·하단 안전 영역 | 장갑·한 손·OS 탐색 영역을 고려. HTML px와 Android dp를 같다고 보지 않음 |
| 삭제·종료는 명시적으로 확인 | 짧은 길게 누르기를 유일한 안전장치로 쓰지 않음. 실제 복구 기능이 있을 때만 실행 취소를 제공 |
| 중요한 알림을 확인할 수 있는 동선 | 금방 사라지거나 다른 모달에 가려지지 않는지, 알림·인수인계 배너가 지도를 가리는지 확인 |
| 움직임 외에도 의미 제공 | 모션 축소 설정을 고려하고, 점멸·이동만으로 상태를 알리지 않음 |

자동 누락·다음 구역 추천·위험도·수색 완료도 계산을 화면 개선이라는 이유로 추가하지 않는다. 기록이 없다는 사실, 경로가 지나갔다는 사실, 사람이 완료 처리한 결과는 다르다. 요약의 지시·추측 대신 원본과 출처를 제공한다.

## 현재 값은 코드에서 확인

- Web 색과 사용처: [tokens.css](../../frontend/src/shared/tokens.css)와 각 feature CSS. `--poli-*`·`--krds-ops-*`는 옛 시안의 이름이며 현재 적용을 보장하지 않는다.
- Android 색·글자·간격·모양: [theme](../../android/app/src/main/java/com/surimap/ui/theme). 화면·공통 컴포넌트 위치는 [Android UI](android-ui-requirements.md)에 연결했다.
- 과거 디자인 참고 자료는 Figma 시안을 재구성한 자료였다. 공식 스타일 전체의 검증·라이선스 확인을 마친 제품 의존성으로 취급하지 않는다.

## 화면을 바꾼 뒤 확인할 것

| 관점 | 실제 화면에서 확인할 내용 |
|---|---|
| 지도·정보 밀도 | 업무폰·마커·여러 차수가 겹칠 때 식별, 사건 전환 뒤 맥락 유지, 시트·배너가 열린 지도 면적 |
| 읽기·접근성 | 글자와 실제 배경의 대비, 색 이외 구분, 200% 확대·키보드 초점·한 손 조작·지도 라벨·모션 축소 |
| 기록·통신 상태 | 오프라인 전환, 미전송·서버 수신·처리 불가 구분, 실패한 영역만 재시도, 입력 보존 |
| 위험한 조작·권한 | 삭제·종료 확인, 취소 가능성, 앱·웹·사건 배정별 실제 서버 거부. 버튼 숨김만으로 끝내지 않음 |
| 사용 환경 | 야외·야간·장갑·화면 크기·글꼴 배율을 필요한 범위에서 직접 확인 |

옛 G1~G6의 5초 식별·10초 비교·3탭·장갑 입력 정확도 90%·대비 4.5:1/7:1·50,000lux 등의 값은 제안이지 검증된 합격선이 아니다. 실제 시험에서는 목적·근거·환경·확인할 결과를 먼저 정한다. 토큰 전체와 목표 수치 표를 코드·문서 양쪽에서 유지하지 않는다.

검증 기록에는 버전·입력·환경·수행 조작·관찰 결과·미확인 범위를 남긴다. 캡처 환경의 한글 폰트 설치 여부를 확인하고, 시안 본문과 검수용 메타를 분리해 실제 화면 면적을 판단한다. 과거 QA의 범위와 보존 검토는 [자료 안내](README.md#실기기-qa-자료의-쓰임)를 확인한다.
