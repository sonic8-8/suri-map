# 수리맵 제품 요구사항

수리맵이 누구의 어떤 문제를 해결하고 무엇을 제공해야 하는지 정리한다. 구현·검증 완료 목록은 아니다. `미정`은 실제 구현과 필요한 동작을 대조해 세부 기준을 합의할 항목이며, 기존 제한·권한을 없앤다는 뜻이 아니다.

## 1. Target Users (대상 사용자)

| 사용자 | 역할 | 사용 환경 |
|---|---|---|
| 현장 수색자 | 현장에서 수색하고 경로·현장 기록을 남긴다. | Android 업무폰 |
| 현장 지휘관 | 수색 현황을 확인하고 구역 관리·인수인계를 지휘한다. | 웹 상황판 |

도보·차량 수색, 장시간 수색과 통신이 불안정한 환경을 고려한다.

## 2. Pain Points (겪고 있는 문제)

- 무전과 메모만으로는 어느 팀이 어디를 수색했는지 파악하기 어렵다.
- 근무 교대 시 다음 근무자가 이전 수색 내용과 이어서 확인할 사항을 파악하기 어렵다.

## 3. Goals (제품 목표)

| 목표 | 사용자 관점의 확인 기준 |
|---|---|
| 수색 현황 파악 | 업무폰의 이동 경로, 사람이 완료 처리한 구역과 현장 기록을 지도에서 함께 확인할 수 있다. |
| 통신 단절 시 기록 보존 | 통신이 끊겨도 현장 기록을 남기고, 복구 후 누락·중복 없이 공유할 수 있다. |
| 인수인계 지원 | 다음 근무자가 이전 수색 기록과 메모를 찾아 인수인계 내용을 파악할 수 있다. |

## 4. Scope (제품 범위)

- **지원**: 경찰의 실종 수색을 위한 현장 기록, 수색 현황 공유와 인수인계.
- **제외**: 공식 사건 기록·무전의 대체, 실제 출동·지원 승인·장비 제어.
- **시연**: 실제 경찰 시스템에 직접 연결하지 않고 mock·seed의 사건과 배정 결과를 사용한다.
- **미정**: 지원할 단말·브라우저의 세부 범위.

## 5. Requirements (요구사항)

### 사건·상황판

- 배정받은 사건을 가져와 실종자 정보·업무폰 경로·구역·현장 기록을 함께 확인한다. 사건에 배정된 계정만 접근한다.
- 여러 지휘관이 같은 사건을 함께 볼 수 있어야 한다. 현장 수색자는 업무폰에서 실종자 정보와 지도를 확인한다.
- **미정**: 계정·권한의 세부 기준. 상황판 허용 지연은 [Issue #8](./issues/8-gps-collection-transmission-basis.md)에서 측정하고 정한다.

### 경로 기록

- 업무폰별 수색 경로를 기록하고 시작·일시정지·재개·종료 상태를 구분한다. 경로의 주체인 업무폰과 당시 조작 계정을 구분하며, 사건과 무관한 상시 위치 추적은 하지 않는다.
- 장시간 수색 중 화면이 꺼지거나 앱이 백그라운드로 전환돼도 경로 기록을 이어간다.
- 도보·차량 구간을 구분해 보고 잘못 분류한 구간은 웹에서 보정할 수 있어야 한다.
- **미정**: 도보·차량 분류의 세부 기준. GPS 수집 주기·묶음 전송 기준은 [Issue #8](./issues/8-gps-collection-transmission-basis.md)에서 측정하고 정한다.

### 구역 관리

- 지휘관이 구역을 배정하고 완료·재개 등 상태 변경과 이력을 남긴다. 업무폰에는 배정 구역 밖으로 표시된 위치를 확인하도록 안내한다.
- 이동 경로가 있다는 사실만으로 수색 완료를 판단하지 않는다. 시스템이 확인 누락·위험도·다음 수색 구역을 자동으로 판단하거나 지시하지 않는다.

### 현장 기록·알림

- 현장 수색자는 단서·실종자 발견·지형 상태·지원 요청 등을 마커로 남기고 사진·메모를 첨부한다.
- 발견·지원 요청처럼 전달이 필요한 기록은 관련 사용자에게 알린다.
- **미정**: 사진 첨부 제한의 세부 기준.

### 오프라인 사용·동기화

- 사건·실종자 정보·지도·배정 구역을 미리 내려받아 사용한다. 통신이 끊겨도 경로·마커를 보관하고 복구되면 미전송 기록을 자동으로 동기화한다.
- 통신 단절·재전송으로 기록이 유실되거나 중복 생성되지 않아야 한다. 미전송 기록은 서버 반영을 확인하기 전에 지우지 않는다.
- 현장에서 기록한 시각과 서버에 동기화된 시각을 구분한다. 오래된 위치를 현재 위치처럼 보여주지 않는다.
- **미정**: 복구 목표 시간은 [Issue #8](./issues/8-gps-collection-transmission-basis.md)에서 측정하고 정한다. 과거 시험 조건을 확정된 GPS 수집·전송·상황판 지연·복구 기준으로 사용하지 않는다.

### 인수인계·이력 확인

- 지휘관은 웹에서 수색 차수를 전환한다. 수색 차수는 사건 내 수색 이력을 묶는 단위이고, 근무 교대는 업무폰을 인수해 근무한 구간이다. 둘을 같은 전환으로 취급하지 않으며, 새 차수를 열어도 이전 기록을 보존한다.
- 이전 수색 차수와 근무 교대의 경로·마커·완료 구역·메모를 확인하고 비교한다. 기록된 사실을 바탕으로 수색 이력을 짧게 요약한다.
- 요약에 기록에 없는 판단을 추가하지 않는다. 미전송 기록이 남아 있으면 최종 요약으로 취급하지 않고, 생성 실패 시 정상 요약처럼 보이는 대체 문장 대신 실패 상태와 원본 기록을 제공한다.

### 사건 종료·정보 파기

- 사건 종료는 되돌리지 않으며 사용자 재오픈 기능을 두지 않는다. 종료 시 실종자 개인정보·사진을 운영 DB·API 응답·단말 자료에서 제거해야 한다.
- **미정**: 데이터 파기의 세부 기준. 파기 시점과 미전송 기록 처리가 충돌하지 않는지는 별도로 검증한다.

## 과거 요구와 출처

팀 프로젝트 당시의 상세 요구·절 번호·FR 번호와 인터뷰 반영 이력은 [축약 전 PRD (`93072f1d`)](https://github.com/sonic8-8/suri-map/blob/93072f1d728f8085bc6d13d6c466bb0788ee076d/docs/prd.md)에서 확인한다. 옛 Spec·시연 기록·주석의 PRD 번호는 이 원문을 가리킨다.

원문의 일정·시험 수치·권한·보존 기간은 작성 당시 계획이며, 현재 구현·검증 완료를 뜻하지 않는다. 원문에 출처로 적힌 인터뷰·요구사항 문서의 사본은 현재 저장소에 없다.
