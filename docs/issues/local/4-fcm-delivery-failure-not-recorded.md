# 제목

[BE] FCM 전송이 실패 결과를 반환해도 로그에 남지 않는 문제

# 본문

## 문제 배경

마커 알림을 업무폰에 보내지 못했다면 어느 이벤트의 전송이 실패했는지 확인할 수 있어야 합니다. 마커 저장이 성공했다는 사실만으로 업무폰의 알림 수신까지 성공했다고 판단할 수는 없습니다.

현재 FCM 전송은 예외를 던지는 대신 `DispatchResult`에 성공·실패 수를 담아 반환할 수 있습니다. 그러나 `MarkerNotificationService.sendFcm()`은 반환값을 사용하지 않고, 예외가 발생했을 때만 경고를 남깁니다. `IncidentAssignmentFcmDispatchService.dispatchAssignmentChanged()`도 같은 방식입니다.

### 문제 해결: 체크리스트

- [x] 실패 반환과 예외 발생의 처리 차이를 확인했는가?
- [x] 기존 마커 테스트에서 FCM 실패를 주입했을 때 실패 기록이 누락되는지 확인했는가?
- [ ] 두 호출부에서 전체·부분 실패를 구분해 이벤트 ID와 실패 수를 기록하는가?
- [ ] 토큰·전체 알림 본문을 기록하지 않으면서 성공·실패를 구분할 수 있는가?
- [ ] 마커 저장·커밋 후 전송 동작을 보존하고 실패 기록을 검증했는가?

## 확인 결과

2026-09-15 기존 마커 테스트의 실패 주입 2건은 DB 저장 보존 검증을 통과했지만, 해당 FCM 경고는 0건이었습니다. 별도 로그 검사는 실패했습니다. 실제 Google FCM이나 Android를 사용한 결과는 아닙니다.

수정 후보는 반환값의 실패 수를 확인해 최소한의 진단 기록을 남기는 것입니다. 자동 재시도 횟수·간격이나 알림 보장 범위는 아직 합의하지 않았으며 이번 기록만으로 도입하지 않습니다. 배정 알림의 커밋 전 호출과 롤백 영향도 별도 후속 검증입니다.
