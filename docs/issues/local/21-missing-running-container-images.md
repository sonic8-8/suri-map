# 제목

[Infra] 실행 중인 수리맵의 기존 이미지를 배포 전에 보존하지 못함

# 본문

## 문제 배경

배포한 버전에 문제가 생기면 이전 버전으로 되돌릴 수 있도록 기존 이미지와 설정을 보존해야 합니다. 현재 Jenkins 파이프라인은 새 이미지를 빌드한 뒤, 이 준비가 끝났는지 확인받고 Backend를 교체합니다.

2026-10-07 Jenkins #59에서 이미지 빌드를 마친 후 기존 Backend 이미지를 별도 이름으로 보관하려 했지만, `docker tag`가 `No such image`로 실패했습니다. 실행 중인 컨테이너에 기록된 이미지 ID로 `docker image inspect`를 실행해도 같은 오류가 발생했습니다. 반면 `develop` 태그에는 새 빌드 이미지가 존재했습니다.

준비 도구가 서비스를 중지하기 전에 멈춰 기존 Backend·Frontend·mock-112는 계속 실행 중입니다. 설정 사본은 저장했지만 기존 이미지 보존, 새 최종 DB 백업, 배포 승인은 완료하지 못했습니다. 따라서 캐시 수정 버전의 배포와 브라우저 성능 비교도 보류했습니다. 기존 서비스가 중단되거나 DB 데이터가 손실된 현상은 아닙니다.

### 문제 해결: 체크리스트

- [ ] 기존 실행 이미지와 설정을 보존한 상태에서 새 버전 배포를 진행할 수 있는가?

이미지·설정 보존은 기존에 합의한 배포 승인 조건입니다. 서비스가 실행 중이라는 사실만으로 이 조건을 충족했다고 판단하지 않습니다.

## 원인 분석과 선택지

아직 이미지 조회 실패의 원인은 확정하지 않았습니다. 새 빌드가 `develop` 태그를 바꾼 영향인지, 컨테이너에 기록된 ID와 이미지 저장소의 식별 방식이 다른지, 별도 이미지 정리가 있었는지 구분해야 합니다. 이미지 목록에서 찾지 못한 것만으로 실제 파일까지 삭제됐다고 단정하지 않습니다.

먼저 기존 이미지가 다른 식별자로 남아 있는지 확인합니다. 없다면 이전 소스로 다시 빌드하거나 실행 중인 컨테이너를 별도 이미지로 보존하는 방안을 검토할 수 있습니다. 다만 재빌드는 당시 의존성이 달라질 수 있고, 컨테이너 보존은 실행 후 변경된 파일을 포함할 수 있으므로 원래 이미지와 같다고 간주할 수 없습니다. 복구 방법은 아직 선택하지 않았습니다.

관측 대상은 Jenkins #59의 `77dfc911` 배포 준비입니다. Backend CI 1,415개는 모두 통과했고 첫 배포 승인에서 대기 중입니다. [파이프라인](../../../infra/ci/hetzner.Jenkinsfile)의 이미지 빌드·승인 순서와 실제 Docker 조회 결과를 대조한 문제이며, [로컬 20번](20-slow-paged-search-path-display.md)의 경로 표시 지연과는 별도로 추적합니다.
