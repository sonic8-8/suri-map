# [Android] 수색 중 탭을 이동하면 GPS 기록이 멈추고 수색 시작 버튼이 다시 나타나는 문제

## 문제 배경

수리맵은 사용자가 수색 시작을 누른 때부터 수색 종료를 누를 때까지 이동 경로 하나를 `SearchPath`로 기록한다. 근무 현황이나 인수인계 탭을 여는 동작은 수색 종료가 아니므로, 같은 경로에 GPS 좌표가 계속 쌓여야 한다.

2026년 7월 15일 Galaxy A21s(`SM_A217N`), Android 12 실기기에서 화면을 켠 채 오프라인 수색을 진행했다. 수색 중 다른 탭을 열었다가 지도 탭으로 돌아오자 진행 중이던 수색이 사라지고 수색 시작 버튼이 다시 나타났다. 사용자는 수색 종료를 누르지 않은 상태였다.

수색 시작 버튼을 다시 누르자 기존 경로를 이어서 기록하지 않고 새 경로가 만들어졌다. 앱 내부 DB인 Room과 배포 서버 DB에서 다음 결과를 확인했다.

| 구분 | 경로 ID | 기록 시각 | Room Outbox에 저장된 GPS 좌표 | 확인 당시 상태 |
|---|---|---|---:|---|
| 첫 번째 경로 | `fb5da3dd-1090-49dd-85ff-bdf5b695c993` | `21:37:33~21:50:02` | 76개 | 종료 요청 없이 `RECORDING`으로 남음 |
| 두 번째 경로 | `8ebb8088-5411-4110-a836-7f32a7b9e81f` | `21:50:51~22:18:56` | 239개 | 사용자가 수색 종료를 눌러 `ENDED`로 변경됨 |

첫 번째 경로의 마지막 좌표와 두 번째 경로의 시작 사이에는 49초 동안 GPS 좌표가 없다. 네트워크를 복구하자 두 경로의 시작 요청이 모두 서버에 전달됐다. 첫 번째 경로는 종료 요청이 없어서 계속 `RECORDING` 상태로 남았다.

이 문제를 그대로 두면 수색 대원이 다른 탭을 확인한 동안 지나간 구간이 지도에서 빠진다. 한 번의 수색도 끝나지 않은 경로와 새 경로로 나뉜다. 실기기에서 재현됐고 실제 GPS 좌표가 누락됐으므로 사용자 조작 실수가 아닌 앱 버그로 판단했다.

## 원인 분석과 선택지

문제가 발생했을 때 진행 중인 경로 ID와 시작 시각은 지도 화면인 `SearchMapRoute` 안에 저장돼 있었다. Compose의 `rememberSaveable`을 사용했지만, 지도 탭으로 돌아오는 과정에서 기존 지도 화면을 제거하고 새 화면을 만들었다. 기존 화면이 사라지면서 그 화면이 보관하던 수색 상태도 함께 사라졌다.

GPS 수집 작업도 지도 화면에 묶여 있었다. 지도 화면이 나타나면 수집을 시작하고, 화면이 사라지면 `DisposableEffect`의 `onDispose`에서 수집을 중단했다. 따라서 다른 탭을 보는 동안에는 GPS 좌표가 저장되지 않았다.

오프라인에서는 수색 시작 요청이 앱 내부 전송 대기열인 Outbox에만 남는다. 서버는 아직 시작 요청을 받지 못했으므로 진행 중인 경로를 알 수 없다. 새로 만들어진 지도 화면도 서버에서 기존 경로를 다시 읽어 복원할 수 없었다.

세 가지 방법을 검토했다.

### 지도 화면을 그대로 보관

탭을 이동해도 기존 지도 화면을 제거하지 않는다. 수색 시작 버튼이 다시 나타나는 현상은 막을 수 있지만, GPS 수집이 지도 화면에 묶인 구조는 그대로 남는다.

### 진행 중인 경로를 Room에 저장

지도 탭으로 돌아올 때 Room에서 기존 경로 ID를 읽는다. 새 경로가 만들어지는 일은 막을 수 있지만, 다른 탭을 보는 동안 빠진 GPS 좌표는 복구할 수 없다.

### 수색 상태와 GPS 수집 작업을 지도 화면 밖으로 이동

지도 화면의 부모인 `SuriMapApp`에서 진행 중인 경로 ID와 GPS 수집 작업을 관리한다. `SuriMapApp`은 탭을 바꿔도 사라지지 않으므로 같은 경로에 GPS 좌표를 계속 저장할 수 있다.

세 번째 방법을 선택했다. 현재 확인한 탭 이동 문제를 해결하면서 Room에 별도 상태를 추가하지 않아도 된다. 다만 화면 잠금이나 앱 종료 후에도 GPS 기록을 유지하는 동작은 이번 범위에 포함하지 않는다.
