# [Android] 로그인 세션이 만료되면 오프라인 수색 상태를 복원하지 못하는 문제

## 문제 배경

#11에서 앱을 오프라인으로 다시 실행해도 사건 목록과 진행 중인 수색을 Room에서 복원하도록 수정했다. Room은 앱 안에 데이터를 저장하는 DB다. 복원할 때는 로그인한 사용자의 `accountId`로 사건과 수색 상태를 찾는다.

2026년 7월 22일 Galaxy A21s(`SM-A217N`, Android 12)에서 #12 수정 결과를 확인하던 중 OIDC 로그인 세션이 만료됐다. 당시 Room에는 사건 1건, 진행 중인 수색 1건, 아직 서버로 보내지 못한 Outbox 요청 43건이 남아 있었다.

하지만 앱은 로그인 정보를 지우면서 세션 스냅샷도 함께 지웠다. 세션 스냅샷은 마지막으로 선택한 사건과 수색 차수, 업무폰 정보를 기억하는 값이다. 스냅샷이 사라지자 앱은 Room에서 데이터를 찾는 데 필요한 `accountId`를 복원하지 못했다.

이후 네트워크를 끊고 앱을 다시 실행하자 접속 확인 화면에서 멈췄다. Room에 사건과 수색 상태가 남아 있었지만 사건 목록이나 진행 중인 수색 화면으로 돌아갈 수 없었다.

로그인 세션이 만료되면 이전 인증 정보로 서버에 요청을 보낼 수 없다. 하지만 업무폰에 저장한 사건과 수색 상태까지 삭제할 이유는 없다. 인증 정보와 현장 기록을 함께 초기화하면 통신이 끊긴 현장에서 진행 중인 수색을 이어갈 수 없다.

이번 Issue는 로그인 세션이 만료될 때 스냅샷이 지워지고 오프라인 복구가 막히는 동작을 다룬다. Room에 저장한 현장 기록 자체는 삭제되지 않았다.

## 원인 분석과 선택지

OIDC 세션을 갱신한 결과가 `AuthenticationRequired`이면 앱은 저장한 OIDC 정보를 지운다. 이어서 `clearPolicePhoneContext()`를 호출한다. 이 메서드는 업무폰 정보뿐 아니라 현재 사건 정보도 함께 지운다.

앱은 사건 정보나 업무폰 정보가 바뀔 때마다 세션 스냅샷을 저장한다. 두 정보가 모두 비면 `SuriMapSessionSnapshotStore`가 기존 스냅샷을 삭제한다. 현재 스냅샷에는 `accountId`가 없으므로 OIDC 정보까지 사라진 다음에는 Room에 남은 사건과 수색 상태의 사용자를 찾을 수 없다.

첫 번째 방법은 로그인 세션이 만료돼도 현재 스냅샷을 그대로 유지하는 방식이다. 변경 범위는 작지만 스냅샷에 사용자를 구분하는 값이 없다. 같은 업무폰에 다른 계정이 로그인하면 이전 사용자의 사건 정보와 새 사용자의 로그인 정보가 연결될 수 있다.

두 번째 방법은 Room에 남은 사건이나 수색 상태에서 마지막 사용자를 추측하는 방식이다. 한 업무폰에 여러 사용자의 기록이 남아 있으면 누구의 상태를 복원해야 하는지 정할 수 없다. 앱이 사용자를 임의로 고르면 다른 사람의 수색 화면을 열 수 있으므로 이 방법은 선택하지 않는다.

세 번째 방법은 스냅샷에 마지막으로 확인한 `accountId`를 함께 저장하고 인증 정보와 수색 상태를 따로 관리하는 방식이다. 로그인 세션이 만료되면 OIDC 인증 정보만 지우고 스냅샷과 Room 데이터는 남긴다. 서버 전송은 다시 로그인해 새 토큰을 받을 때까지 멈춘다.

사용자가 다시 로그인하면 앱은 새 토큰의 `accountId`와 스냅샷에 저장한 값을 비교한다. 두 값이 같을 때만 기존 수색 상태를 복원한다. 두 값이 다르면 이전 수색 상태를 열지 않는다. 이전 계정이 만든 Outbox 요청을 새 계정의 토큰으로 보내는 문제는 #6에서 따로 다룬다. 스냅샷의 `accountId`는 기록의 주인을 찾는 데만 쓴다. 서버 접근 권한은 새로 받은 OIDC 토큰으로 확인한다.

세 번째 방법을 선택한다. 사용자가 로그아웃하거나 계정을 바꾸면 현재 스냅샷을 초기화하되 서버로 보내지 못한 기록은 삭제하지 않는다. 이 기록의 작성자를 보존하는 방법은 #6에서 정한다. 업무폰의 모든 데이터를 지우는 일은 관리자가 보내는 MDM 원격 삭제 명령처럼 별도 보안 조치로 처리한다.
