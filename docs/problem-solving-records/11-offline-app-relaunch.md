# [Android] 오프라인에서 앱을 강제 종료한 뒤 다시 실행하면 사건 선택 화면으로 이동하지 못하는 문제

## 문제 배경

2026년 7월 17일 Galaxy A21s(`SM-A217N`, Android 12) 실기기에서 GPS 수집 주기를 비교하려고 디버그 앱 네 개를 차례로 시험했다. 앱마다 주기를 2.5초, 5초, 10초, 30초로 다르게 설정했다. 이 가운데 GPS 수집 주기를 10초로 설정한 앱을 오프라인에서 다시 실행하다가 문제를 발견했다.

당시 이 앱에는 이전에 불러온 사건 정보와 OIDC 로그인 세션 정보가 남아 있어 다시 로그인할 필요가 없었다. 그런데 Wi-Fi를 끄고 앱을 강제 종료한 뒤 다시 실행하자 `접속 확인` 화면에 `내부망 연결을 확인하세요`라는 안내가 나타났다. 앱은 사건 선택 화면으로 이동하지 못했다.

문제가 앱 시작 단계에만 있는지 확인하려고 Wi-Fi를 다시 연결해 사건 정보를 불러왔다. 수색 화면에 들어간 뒤 Wi-Fi를 끄고 수색을 시작하자 경로는 업무폰에 계속 저장됐다. 수색 화면을 먼저 열어 두면 오프라인 기록이 가능했지만 앱을 다시 실행하면 그 화면으로 돌아갈 수 없었다.

수리맵은 통신이 끊겨도 위치와 마커를 업무폰에 저장한다. 이 기록을 이어가려면 앱을 다시 실행한 뒤에도 진행 중인 수색 화면으로 돌아갈 수 있어야 한다. 하지만 현재는 네트워크가 복구될 때까지 그 화면으로 돌아갈 수 없다. 그동안 현장 대원은 같은 경로에 GPS 좌표와 마커를 이어서 기록할 수 없다.

이 문제는 GPS 수집 주기를 10초로 설정한 디버그 앱을 직접 강제 종료한 경우에만 확인했다. Android가 앱을 자동으로 종료한 경우와 배포용 앱에서는 아직 확인하지 않았다.

## 원인 분석과 선택지

`AuthBootstrapCoordinator.check(...)`는 앱을 시작할 때 `GET /api/health`로 서버 연결을 확인한 뒤 업무폰이 사용 중임을 알리는 heartbeat 요청을 보낸다. 서버에 연결하지 못하면 `AuthBootstrapRoute`는 사건 선택 화면으로 이동하지 않는다. 이 때문에 OIDC 로그인 세션 정보와 사건 정보가 남아 있어도 오프라인에서는 사건 선택 화면을 열 수 없다.

접속 확인 화면만 건너뛰어서는 기존 수색을 이어갈 수 없다. `IncidentListStateLoader`는 마지막 사건 목록을 앱 내부 DB인 Room에서 읽지 않고 서버에서만 불러온다. 수색 상태도 화면을 잠시 복원하는 `rememberSaveable`에만 남아 있다. 앱을 강제 종료하면 수색 경로를 가리키는 `searchPathId`와 `ACTIVE`(기록 중) 또는 `PAUSED`(일시정지) 상태를 잃는다.

사건 목록과 수색 상태를 업무폰에 남길 세 가지 방법을 검토했다. 첫 번째 방법은 두 데이터를 간단한 설정 파일인 SharedPreferences에 저장하는 방식이다. 수정 범위는 작지만 서버로 보낼 요청을 쌓아 두는 Outbox는 Room에 있어 수색 상태와 한 번의 저장 작업으로 묶을 수 없다. 수색 시작 요청만 남고 `ACTIVE` 상태는 사라질 수 있다.

두 번째 방법은 현재 수색 상태와 마지막 사건 목록을 Room에 저장하는 방식이다. 수색 상태와 Outbox를 하나의 트랜잭션으로 묶으면 두 데이터가 함께 저장되거나 함께 취소된다. 대신 Room 테이블을 추가해야 한다. 앱을 업데이트해도 기존 Outbox 데이터가 남도록 마이그레이션을 작성해야 한다.

세 번째 방법은 Outbox 요청만 읽어 현재 수색 상태를 다시 계산하는 방식이다. 새 테이블은 필요 없지만 이미 전송한 요청과 보내지 못한 요청이 함께 남을 수 있어 `ACTIVE`와 `PAUSED` 상태를 판단하는 규칙이 복잡해진다.

세 방법 중 Room에 저장하는 방식을 선택했다. Room에서 현재 수색 상태를 찾을 때는 사용자 계정의 `accountId`와 사건의 `incidentId`를 함께 사용한다. 마지막 사건 목록은 `accountId`로 찾는다.

앱을 오프라인에서 다시 실행하면 Room에 저장한 정보를 읽어 다음과 같이 화면을 복구하기로 했다.

- 수색 상태가 `ACTIVE`면 같은 수색 지도로 돌아가 GPS 수집을 재개한다.
- 수색 상태가 `PAUSED`면 같은 수색 지도로 돌아가되 GPS는 수집하지 않는다.
- 진행 중인 수색이 없으면 해당 계정이 마지막으로 받은 사건 목록을 보여준다.

지도 자료가 일부 빠져도 경로와 마커는 계속 기록한다. 이때 화면에는 빠진 지도 자료가 있다는 안내를 보여준다.

OIDC 로그인 세션 정보가 없고 Room에 저장한 수색 상태와 사건 목록도 모두 없다면 사건 선택 화면이나 진행 중인 수색 화면을 열 수 없다. 이 경우에는 네트워크에 연결하라는 안내를 보여준다.

네트워크 연결이 복구되면 서버에서 사건 상태와 계정 배정, 현재 수색 차수(OP)를 다시 확인한다. 사건이 이미 끝났거나 계정 배정이 해제됐거나 수색 차수가 바뀌었다면 GPS 수집을 멈춘다. 이어서 복구에 사용한 수색 상태만 지우고, 업무폰에 저장한 Outbox와 GPS 기록은 그대로 둔다.

이때 OIDC 로그인 세션이 만료된 것으로 확인되면 로그인 화면으로 이동한다. 로그인 화면으로 이동해도 Room에 저장한 데이터는 지우지 않는다.
