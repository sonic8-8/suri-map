# [Android] 화면을 끄면 수색 경로 GPS 좌표가 저장되지 않는 문제

## 문제 배경

수색 중인 대원은 업무폰 화면을 끄거나 다른 앱을 사용할 수 있다. 업무폰을 주머니에 넣고 이동하는 동안에도 수리맵은 경로를 계속 기록해야 한다.

2026년 7월 23일 Galaxy A21s(`SM-A217N`, Android 12)에서 2.5초 간격으로 GPS 좌표를 수집하는 앱을 테스트했다. 수색을 시작하고 화면과 네트워크를 끈 뒤 10분 동안 이동했다. 이때 Android가 위치 요청 간격을 2.5초에서 10분으로 늘렸고, 앱 내부 DB에는 새 GPS 좌표가 저장되지 않았다.

화면을 끈 동안 지나간 경로가 남지 않으면 통신이 복구돼도 해당 구간을 서버로 보낼 수 없다. 지휘 화면에서도 대원이 어느 길을 수색했는지 확인할 수 없다.

이번 결과는 한 대의 업무폰에서 10분 동안 확인했다. 모든 Android 기기에서 같은 문제가 생긴다고 단정할 수는 없다. 다만 현재 앱에는 화면을 끈 뒤에도 GPS 수집을 유지하는 장치가 없다.

## 원인 분석과 선택지

현재 앱 화면이 Android의 `LocationManager`에 GPS 좌표를 요청한다. 화면을 끄면 앱이 백그라운드로 전환되고, Android는 배터리를 아끼기 위해 위치 요청 횟수를 줄일 수 있다.

[Android 공식 문서](https://developer.android.com/develop/sensors-and-location/location/permissions#foreground)는 화면을 끈 뒤에도 위치를 계속 받아야 할 때 포그라운드 위치 서비스를 사용하도록 안내한다. 포그라운드 위치 서비스는 실행 중이라는 알림을 보여 주면서 GPS 수집을 이어 가는 Android 기능이다.

첫 번째 방법은 포그라운드 서비스가 알림만 띄우고, 지금처럼 앱 화면에서 GPS 좌표를 수집하는 방법이다. 변경할 코드는 적지만 앱 화면이 종료되면 GPS 수집도 멈출 수 있다.

두 번째 방법은 포그라운드 위치 서비스가 GPS 좌표 수집과 저장을 맡는 방법이다. 앱 화면은 수색 시작과 중지 명령만 서비스에 전달한다. 화면을 꺼도 GPS 좌표를 받을 수 있지만, 수색 중에는 알림이 계속 보이고 배터리를 사용한다.

두 번째 방법을 적용한다. 수색을 시작하면 포그라운드 위치 서비스를 실행하고, 수색을 멈추거나 끝내면 서비스를 종료한다.

## 변경 내용과 트레이드오프

수색을 시작하면 `SearchPathLocationService`가 포그라운드 알림을 띄우고 GPS 좌표를 수집한다. 앱 화면은 수색 상태에 따라 서비스를 시작하거나 멈추는 역할만 맡는다. 수색을 멈추거나 끝내면 남은 좌표를 앱 내부 DB에 저장한 뒤 서비스를 종료한다.

앱이 저장된 수색 상태를 불러오기 전에는 서비스를 멈추지 않도록 했다. 위치 권한이 없으면 수색 시작 전에 권한을 요청하며, 권한을 받지 못하면 서비스도 GPS 수집을 시작하지 않는다.

수색 중에는 포그라운드 알림이 계속 보이고 배터리를 사용한다. Android가 앱 프로세스를 종료했을 때 오래된 수색 명령을 자동으로 다시 실행하지 않도록 서비스는 `START_NOT_STICKY`로 동작한다. 앱을 다시 열어 진행 중인 수색을 불러오면 서비스를 다시 시작한다.

변경 내용은 `fd16c478`에 반영했다.

## 검증 결과

2026년 7월 23일 Galaxy A21s(`SM_A217N`, Android 12)에서 5초 간격 앱으로 확인했다. 네트워크와 화면을 끈 상태를 2분 이상 유지했다.

`adb shell dumpsys location`에서 화면을 끈 뒤에도 앱이 포그라운드 상태를 유지했고, 위치 요청 간격도 5초로 남아 있었다. 이전 테스트처럼 10분으로 늘어나지 않았다.

같은 시간에 앱 내부 DB에는 GPS 좌표 8개가 전송 묶음 4건으로 저장됐다. 다만 실제 좌표는 약 20초마다 들어왔고 모두 네트워크 위치였다. 이번 테스트는 화면을 꺼도 좌표 저장이 이어지는지만 확인했다. 5초마다 새 좌표가 들어오는지와 이동 경로 모양은 확인하지 않았다.

다음 명령으로 전체 단위 테스트와 Debug APK 빌드를 실행했다.

```bash
cd android
./gradlew test :app:assembleDebug
```

결과는 `BUILD SUCCESSFUL`이며 실행 시간은 7분 9초다. 이번에 바꾼 `main`과 `test` 소스의 ktlint 검사도 통과했다.
