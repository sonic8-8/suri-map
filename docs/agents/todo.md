# TODO 작성

TODO는 목표와 그 목표를 이루기 위한 작업의 완료 여부를 적는다. TODO Issue와 그 아래 TODO Task 두 단계로 써서, 무엇을 왜 하는지와 다음에 할 일을 함께 보게 한다. 두 용어의 뜻과 GitHub Issue, 티켓과의 구분은 [`GLOSSARY.md`](../../GLOSSARY.md)를 따른다.

## TODO Issue

TODO Issue는 여러 TODO Task로 이룰 목표 하나다.

- 제목(what): 무엇을 할 것인가. 작업 대상과 변화의 핵심만 남겨 명사형으로 쓴다.
- `의도:`(why): 왜 하는가. 이 일을 하는 이유로 시작한다. 지금 무엇이 부족하고 이 작업으로 무엇을 가능하게 하려는지 쓴다.
- TODO Task(how): 어떻게 이룰 것인가. 아래 체크박스로 나눈다.

목표 문장으로 완료를 판단할 수 있으면 완료 기준을 따로 쓰지 않는다. 판단이 모호하면 목표를 구체화하고 필요한 조건만 덧붙인다.

## TODO Task

TODO Task는 TODO Issue를 이루려고 나눈 하위 작업이다. 제목은 작업 대상과 핵심 작업이 드러나게 명사형으로 쓴다. 세부 방법은 작업을 시작할 때 구체화한다. 이미 합의한 조건은 해당 TODO Task 아래에 남긴다.

## 배치

TODO Issue와 TODO Task는 진행 순서대로 둔다. 선행 작업, 수행 조건, 자료 링크는 해당 TODO Issue나 TODO Task 아래에 둔다. 상세 설계와 실행 기록은 담당 문서에 두고 링크로 연결한다. 같은 작업은 담당 TODO 한곳에서 관리하고, 다른 곳에서는 그곳을 참조한다.

여러 TODO Issue에 걸친 공통 배경, 의도와 선후 관계는 관련 TODO Issue 앞에 `Context:` 문단으로 한 번만 쓴다. 여러 대상의 입력과 결과를 함께 말하면 어느 대상의 것인지 밝힌다.

## 완료와 갱신

`[x]`는 완료를 확인한 것이고 `[ ]`는 확인하지 않은 것이다. TODO Task는 결과를 확인했을 때 체크한다. TODO Issue는 목표 달성을 확인했을 때 체크한다. TODO Task를 모두 끝내도 목표에 닿지 못했으면 TODO Issue를 열어 두고 TODO Task를 조정한다. 완료한 항목은 체크해 남긴다. 오래된 완료 항목이나 철회한 작업을 정리할 때는 결과, 한계와 근거를 기존 기록에 보존하고 연결한다.

상세 진행 상황과 미완료 사유는 기존 작업 기록에 남긴다. 다시 시작할 때는 합의 범위와 완료 근거를 먼저 확인한다.

## 예시

```markdown
- [ ] **Issue: 새 경로 조회 API의 상황판 동작 검증**
  - 의도: 지휘자는 상황판의 경로를 보고 어디를 이미 수색했는지 판단한다. 그런데 차수, 사건, 지도 style을 바꾸거나 다시 접속했을 때도 경로가 실제 기록대로 보이는지는 아직 확인하지 않았다. 이를 확인해 지휘자가 상황판만 보고 수색한 곳을 믿고 판단할 수 있게 한다.
  - [ ] 지도 변경분 반영의 실제 차수, 사건, 지도 style 전환 검증
  - [ ] 새 경로 조회 API의 상황판 Smoke Test
    - 배포본, 측정 스크립트, Ops k6 스크립트의 버전과 테스트 계정, FCM 안전 조건을 확인한다.
```
